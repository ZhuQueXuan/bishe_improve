# 规划｜Agent工具调用

最后更新：2026-10-04  
状态：最小有限工具循环已实现；当次轨迹、本地保存/离线重放、预算与停止验证通过；正式长期轨迹和真实答案评测尚未完成

## 阶段目标

让系统根据用户问题选择检索工具、观察结果并在有限步骤内决定是否继续检索，形成可解释的单 Agent 工作流。

## 候选工具

- `search_entities`：查找疾病、症状、药品等候选实体。
- `get_entity_detail`：获取疾病描述、病因、预防和治疗属性。
- `get_graph_relations`：查询有限的一跳或两跳关系。
- `search_medical_text`：根据DeepSeek整理的条件查询医疗原文全文索引。
- `verify_evidence`：判断现有证据是否足以回答。
- `answer_with_evidence`：仅基于证据生成回答和引用。

## 计划任务

- [x] 最小工具输入/结果/错误与来源格式（复用图谱和全文能力）。
- [x] 检索默认只读，固定参数和数据范围。
- [x] 最多3次检索含baseline、一次理解/一次回答，步骤截止预算与SDK/事务超时接线。
- [x] 根据观察选择补查、停止或回答的有限循环。
- [x] 当次API轨迹，以及本地验收轨迹保存/离线重放。
- [x] 不展示模型隐藏推理、不在轨迹写历史或异常秘密。
- [x] 工具故障、空/部分证据、重复、次数/时间耗尽停止。
- 尚未实施：正式账号长期结构化轨迹保存、医学语义冲突审核、完整真实答案忠实度/成本测量；不由上述勾选推断完成。

## 后续记忆系统（已记录，当前不扩展）

当前基线只使用“最近 10 条消息”作为短期对话记忆。这能先验证指代理解和连续追问，但随着对话变长会带来上下文丢失、无关信息干扰、模型成本上升和医疗隐私风险。

后续待 RAG 检索和 Agent 工具基线稳定后，再基于真实失败案例逐步实现：

- 短期记忆：保留最近对话，超出窗口时生成可追溯摘要。
- 长期记忆：只记录经用户确认的偏好、关注主题和稳定事实，不把模型推测当作医疗事实。
- 语义检索：按当前问题检索少量最相关记忆，而不是每次发送全部历史。
- 图谱记忆：记录“用户当前正在询问哪个疾病/药品/症状”，用于解析“它”等指代并辅助图检索。
- 记忆治理：用户可查看、编辑、删除和关闭记忆，为敏感医疗内容设置明确保留期。
- 记忆评测：测量指代解析、跨轮事实一致性、无关记忆干扰、隐私泄漏、延迟和 token 成本。

在上述评测和用户控制机制建立前，不把当前的短期历史窗口宣称为完整 Memory 系统。

## 验收标准

- 不同问题类型会触发不同工具组合。
- Agent 不会执行无限循环或无限制 Cypher。
- 工具调用轨迹能够解释答案依据。
- 证据不足时继续检索或明确拒绝猜测。
