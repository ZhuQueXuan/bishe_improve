# 过程｜图谱数据工程与正式部署

覆盖原06～13；过程发生于2026-10-03，2026-10-05合并。本文按“核验旧数据→准备样本→安全导入→验证全量→只读适配→正式切换→退出旧内容”保留连续过程。后续查询理解和Agent能力不在本阶段冒称完成；当前入口见[00](00_项目现状与快速接手.md)。

## 1. 为什么先核验数据

旧库有70,620节点、340,633关系，空名称、重复节点/关系等结构检查为0，但原处理过程会推导药品商品名/厂家。原始8,808条疾病记录只有8,807个不同病名；旧关系文件1,197,753条，去重后340,813条，其中drugs_of有856,672条重复。文件与数据库还存在241条仅文件有、4条仅数据库有的关系差异。结构整洁不能证明加工合理，不能直接重用旧导入，更不能让普通导入默认清库。

决定：保留原JSON，实体/关系只取可追溯原值，不编造商品或厂家。先用40疾病检验流程，再处理全量；数据全部保留not_verified，不把工程检查称为医学审核。

## 2. 40疾病样本与小样本导入

样本按八组各五种选取，是工程覆盖选择，不是医学重要性排名。名称清理只去空白，拒绝占位、控制字符、截断名称；不猜测补全。每条资料记录原始文件哈希、行号、记录、字段及列表位置。候选4,522条、不合格4,286条；排除理由可以重叠，不能相加当疾病总数。

最终40疾病、1,390实体、2,138关系：293症状、244检查、13治疗方式、432药品、347食物、21科室，另40疾病；不生成Producer。13项数据测试、稳定重生成与逐项出处核验通过。药品详情保留原文，不能拆成未经核验的品牌节点。

safe_import_curated默认离线，不读凭据或联网；在线检查与实际写入分开。写入绑定输入/代码哈希、明确URI与数据库及审核记录；唯一键dataset_id+id，内容冲突拒绝覆盖。一个受控数据范围用标记锁和单个业务事务，异常整体回滚；白名单关系类型、参数化值、无清库语句。命名空间不自动隔离旧MATCH(n)，读取也必须限定dataset。

真实测试复用Neo4j Community 5.25.1，独立17687/17474端口、本机临时实例：

| 检查 | 结果 |
| --- | --- |
| 首次导入 | 1,390业务实体、2,138关系，另一个标记 |
| 相同输入再执行 | 新增0，原属性及出处一致 |
| 完整写入后真实异常 | 故障数据范围全部回滚，样本不变 |
| 样本dump恢复到新目录 | 1,391节点含标记、2,138关系，完整属性/出处一致 |
| 旧库只读前后统计 | 70,620 / 340,633不变 |

临时无认证仅用于独立测试，不沿用到正式服务。样本备份恢复不代替旧业务库备份。

## 3. 全量处理与分批恢复

全量保留8,806疾病、27,098实体、301,314关系。实体分布：疾病8,806、症状5,643、检查3,353、药品3,828、食物4,870、治疗544、科室54。图比旧图小主要因为取消商品变体和去重，不能误读为只导入样本。

原始记录处理决策：第892行“无标题文档”排除但原文留存；“胎膜早破”选择第8771行代表、第1739行保留为重复副本，不混合字段。跳过994个截断名称，记录263个同字段重复；402个宜吃/忌吃冲突方向均不入图，不替医学判断。163,290条商品详情不生成品牌/厂家；52处缺失或无效文本不填补。177,402个处理事项不是排除的疾病数。七项全量测试、六个生成文件字节一致检查通过。

safe_import_full每批最多500条，共663业务批。单批数据与进度同事务：失败批回滚，前面成功批保留，不宣称整个全量事务回滚。续传前验证已提交前缀、计划/目标/代码哈希和完整来源；未知、缺失或冲突记录均拒绝。所有属性、关系端点与出处完整比较后才标complete，未完成范围不能回答问题。本机当次峰值约1.55GB，不作为跨机器性能保证。

独立18687/18474测试：第六批故障，前五批2,500实体保留、进度仍5；恢复写入24,598实体及全部关系，663批完成；再次执行新增0；dump恢复新目录后27,099节点含标记、301,314关系及完整出处一致。小样本数据13项、导入17项、全量协议7项离线检查通过。此时旧库仍仅只读，不能把测试完成写成已正式切换。

## 4. 只读问答适配，再正式部署

先适配entity_type、properties_json与来源JSON，限制medical_full_v1+complete；只读事务，固定关系/字段，来源异常拒绝，不回旧库掩盖问题。18个真实检索问题和本地API模拟回答通过；首轮17项后端测试含5项历史场景。一次查询变量冲突已修复。厂家/品牌问题明确不支持，零模型调用。每类关系8项等检索边界后来单独摸底，未因此宣称复杂问法完成。

用户随后确认启用全量、跳过当时的真实外部模型验收。旧业务neo4j.dump及system.dump先恢复至19687/19474独立实例；核对属性、标签、关系及端点指纹，不能用内部ID当恢复一致标准。然后优雅停止旧服务，以新的正式目录neo4j_full_v1导入，绑定正式目标计划。正式端口7687/7474仅本机、启用认证，恢复原system账户；业务由新程序导入，不复制未经核验的测试业务库。

正式663批完成，27,098业务实体/301,314关系与原文件一致。部署标记ready、统计排除标记，启动必须用项目scripts/start.ps1。新正式dump已有留存，但不能把某一新dump留存等价成该份dump已另做恢复实验。18项测试与四项HTTP健康检查当次通过；旧写接口早期403，随后清理时移除为404。

## 5. 旧内容退出活跃项目

原13逐项归档100个明确路径：39个旧源码/数据/数据库目录、61份过程材料，记录在Old/cleanup_20261003。退出旧图谱管理页面、组件/状态库、导入/写API及不再使用的依赖声明；保留原JSON、full_v1、40疾病回归样本、账号历史、正式环境与运行依赖，不以目录整齐为理由移动全部环境。

导入代码指纹变化后的完成库只接受相同输入经完整只读校验，不偷偷改完成标记。清理后18后端+46数据/导入离线检查、六文件字节重生成、前端lint/build、18检索与全量只读核验通过；没有图谱写入或重导。

## 6. 阶段结论与后续边界

数据准备、安全导入、真实故障恢复、备份恢复、只读适配及正式切换均已完成，不能再把“替换旧库”当待办。医学专业审核仍未完成；原始文件不改，日后重要修改保护的是当前版本，不能用旧版本已有备份代替。阶段初期的外部验收取消，只限那次；后续有另获授权的有限Flash实验，不写成永远禁止使用模型。

正式数据入口：[full_v1](../bishe/data/full_v1/README.md)、[curated_v1](../bishe/data/curated_v1/README.md)。历史证据部分在此前清理时已退出temp；下方原记录保留其当时路径，缺失材料不假称仍可打开。下一段过程见[检索基线与使用验收](07_过程_检索基线与聊天验收.md)。
