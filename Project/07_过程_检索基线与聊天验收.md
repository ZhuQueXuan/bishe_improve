# 过程｜检索基线与聊天验收

覆盖原14～17，过程发生于2026-10-03，2026-10-05合并。把“检索到底会什么”和“页面是否能正常使用”分开记录；当时尚未接全文/Agent是历史状态，当前见[00](00_项目现状与快速接手.md)。

## 1. 固定50题摸底，而非挑成功例子

题集含原18题和32道新增题，旧图谱baseline严格通过23/50、失败27/50。原18全部通过，新题5/32。588条返回事实出处均核验，不代表每道题找全或回答正确。

| 题型 | 通过/总数 |
| --- | --- |
| 原有代表题 | 18/18 |
| 换说法 | 0/8 |
| 症状反查 | 0/6 |
| 多条件/嵌套名称 | 0/4 |
| 多轮 | 2/6 |
| 边界 | 2/4 |
| 完整列表/组合 | 1/4 |

主要失败：征兆/防范不能稳定映射字段；多尿、多饮反查和AND条件未实现；省略追问缺对象；胃炎/慢性胃炎的嵌套识别；否定或比较处理不足；不存在名称包含已有名称误命中；关系每类限8项却未明确提示省略。库中确有“糖尿病和高血压”等复合名，不能随意认作坏数据。

原题目标覆盖86.5%，换说法目标覆盖80.6%但精度仅6.5%，解释了“返回很多有出处资料仍失败”。用户选择暂缓检索细节，保留失败而不改题或重导。23/50是这套题的旧检索分数，不是医疗问答准确率。

证据：[冻结题集](../bishe/data/retrieval_baseline_v2.json)、[结果](../bishe/data/retrieval_baseline_v2_results.json)、[逐题检查](../bishe/data/retrieval_baseline_v2_review.md)。八项离线检查、两次真实只读测量一致，无模型调用/图谱写入。

## 2. 用户要求推动的两项聊天调整

普通聊天隐藏[E1,E2]及出处附录，仅显示层处理，接口和已保存原答案保留证据；用户输入里的普通[1]不误删。新消息与历史消息共用messageDisplay.js，lint/build及临时显示检查通过。后来的工具轨迹入口不自动恢复聊天正文来源显示。

游客新建对话改为追加，侧栏支持本次多会话搜索、切换、删除；SPA内切页保留，刷新仍清空。登录历史仍由账号存储，身份切换隔离，不能把游客内存功能写成跨刷新持久化。

## 3. 真实页面使用与权限验收

17项页面操作、6项HTTP权限检查在独立8001后端+temp SQLite、现有8080前端完成；使用模拟模型、真实只读图谱。应用内浏览器连接失败后用隐藏Chromium验收，没有操作用户登录浏览器或正式账号历史。

检查覆盖游客多对话/搜索/删除/刷新；注册校验与自动登录；加载期间禁重复发送；登录多轮与刷新保留；请求失败后恢复；登出、第二账号隔离、错误密码、重新登录第一账号、删除持久化。跨账号GET/PATCH/DELETE/QA均404，游客访问受保护资源401。

实际发现并修复：注册后加载历史与创建空会话竞争导致重复空对话，新增syncing门控；补注册FirstAidKit/Memo/Food图标；登录问答按服务端文本保存。修改前四份前端文件有当前版本备份。正式原JSON、账号库和图谱未写入，无付费模型验收。

证据：[使用验收](../bishe/data/usage_acceptance_20261003.json)。当时temp页面/API报告与截图路径见下方原记录，旧材料可能已归档。四项健康检查为当时200，不保证服务一直在线。

已完成：本机运行与全量库、可追溯图检索baseline、游客/登录聊天基本交互与权限检查。未完成的全文、理解和有限Agent后来依次补齐，不能沿用原17“下一步做向量”的建议。检索细节仍暂缓；医学审核、异机复现及旧密钥废止确认不因页面检查而完成。
