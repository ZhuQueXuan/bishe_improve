# 过程｜全文检索与DeepSeek路线调整

覆盖原18～23，2026-10-03～04过程，2026-10-05合并。顺序为可追溯全文→本地语义准备→Flash查询理解→真实小样本→本地对照→退出向量。最终决定是Flash理解后查真实图谱/全文，本地模型及向量路线取消，不按早期下载计划继续。

## 1. 全文能力先独立验证

medical_text_v1由full_v1保留的8,806疾病原文生成149,975片段：描述8,842、病因15,873、预防9,976、症状54,706、检查39,530、治疗21,048。每片段最多600个Python字符，后半段优先句末分割、无重叠，列表逐项切分；保留行号/记录、字段/index、源哈希及[start,end)位置，不改字、不补缺，not_verified。

Neo4j 5.25.1实际使用cjk分析器和queryNodes，medical_fulltext_v1索引现有CuratedEntity的name、properties_json。149,975片段在磁盘，未逐片段入库；实际工具查疾病描述/病因/预防中的原文字面短语，不是六类片段都支持全文搜索，也不是向量召回。

输入1～200字，转义为带引号Lucene字面量，不接受任意操作符；候选/结果限额、每条最多600字且出处核验。建索引绑定目标/DDL/代码/原文哈希，必须精确确认；同名不一致拒绝，未就绪不能检索。唯一数据库变更是增加该全文索引，业务数和原JSON不变。初次序列化审计失败发生于建索引前，修复后完成；再次执行created=false。

11项测试、149,975片段原文/位置/重生成检查通过。8个固定原文短语全文8/8、按病名图工具0/8，36证据出处正确；既有50个自然问句整句送字面工具0命中，表明需要查询理解，不能将它与图baseline23/50直接比较。18图检索回归、四健康检查当次通过，无外部调用。

证据：[文本说明](../bishe/data/medical_text_v1/README.md)、[全文对照](../bishe/data/fulltext_comparison_v1.json)。

## 2. 本地准备与用户改变路线

早期选bge-small-zh-v1.5 revision7999e1d3359715c523056ef9478215996d62a620，下载权重约91.9MiB，但独立CPU环境约3.19GiB、缓存约631MiB，合计约3.89GiB。原19记录的是准备完成尚未推理，不能与后来22实验混为同一时点。

用户据此要求今后下载前说明名称、权重、位置、依赖/缓存和运行资源，并明确批准；那次下载发生于规则提出前，不能补写成已依该流程批准。随后优先Flash理解，不用Jev，先暂停本地实验；后来单独批准使用已下载模型做对照，最后明确退出本地/向量。三个决定按时间保留，当前不能恢复。

## 3. Flash理解接入与首次真实12题

先原图只读baseline确认可用；Flash仅理解当前问题，输出受约束JSON：medical、diseases、fields、keywords。最多3疾病/5字段/3短语，病名必须在当前问题出现，不准生成查询语句。一次理解15秒/600输出token、零SDK重试；非法格式/推断病名等回原baseline，真实工具故障报错不假装空资料。有病名走字段图检索，无病名可按文本短语全文查，原计划最多三次搜索。此时是固定分支，尚无观察后再次选择。

29后端模拟检查、10固定模拟计划+真实只读工具场景（33事实核验）、18图检索回归通过。一次拟多发历史的变更被自动审批拒绝，改为只当前问题后完成，没有绕过原外发范围。最初deepseek-chat不在当时官方模型列表，用户批准本次试验用Flash，正式切换到下一阶段才做。

冻结12题：8换说法、2追问、2边界；旧2/12、Flash10/12。11次实际理解请求（品牌边界本地拒绝0请求），430条事实含重复出处正确。失败是省略“那检查呢”没有对象，以及XYZ名称包含已知名的baseline误命中。只有理解/检索，无最终答案。

当次平均额外耗时1,850.45ms，不能当系统普遍延迟。实际输入3,208/输出3,763tokens，估算0.00255084美元，以预算系数8折约0.0204元；不是账户账单。用户12次/1元授权该批已结束。

证据：[12题真实报告](../bishe/data/query_planning_live_results_20261004.json)。合并不重跑或改报告。

## 4. 正式Flash切换与已有BGE对照

用户批准正式.env切deepseek-flash并重启后端，当前配置事先备份；本地对照零额外模型调用/下载。40疾病、13资料字段、2,543向量，CPU4线程、512维、CLS归一化，分词窗口最大512tokens并保存偏移，不静默截断；没有Neo4j向量索引。

首轮编码34.87秒、流程46.75秒（不含此前JSON加载失败）；向量约4.97MiB、观察峰值内存1.72GiB。小向量文件不代表依赖磁盘占用小。

12题中慢性胃炎/支气管炎不在40样本，对照只取10共同目标题：Flash严格8/10，向量无历史或有历史均1/10；八个正题top1分别7/8、5/8、6/8，top5精度87.5%、37.5%、47.5%，目标出现87.5%、75%、87.5%。Flash查全量、向量查样本，候选池不相同；不能称公平全量检索排名。8个无病名探针向量top1为6/8、top5目标7/8，没有Flash配对；4个无关问题仍返近邻，拒绝阈值未校准。热查询约9.7～10.8ms与历史Flash1.85s不是同时条件性能对照。

## 5. 退出与阶段结论

用户最终停止本地小模型、全量embedding、向量索引和三路融合。原23逐项移出13路径，记录当时约3.90GiB；Old/local_embedding_20261004后续只读审查发现已不存在，不推断删除过程、释放空间或重新下载。历史指标仍保留，但原模型/清单链接不可用。主后端环境、Flash正式配置、全文数据和工具继续使用。

取消是已退出路线，不是“还欠一套向量功能”。全文和Flash已接入，有限Agent闭环是在后续实现；证据状态保持not_verified。后续见[Agent闭环与技术深度复审](09_过程_Agent闭环与技术深度复审.md)。
