## 2. BoundedAgent落地

流程：原图baseline确认可读→Flash理解当前问题一次→校验条件→观察病名/字段覆盖→缺项选择尚未执行的图/全文查询→再次观察→足够时一次回答，或明确停止。

代码：[agent_loop.py](../bishe/knowledge_graph_backend/api/agent_loop.py)、[read_tools.py](../bishe/knowledge_graph_backend/api/read_tools.py)。每次最多3检索含baseline、1理解、1回答、90秒。重复动作不再执行；无证据或覆盖不足不生成，来源/工具故障503、截止耗尽504，失败不写聊天历史。SDK零重试、Neo4j READ事务与剩余超时实际接线；迟到结果丢弃，90秒不是强杀任意阻塞线程保证。

按每疾病/字段覆盖；无病名全文不能把不同疾病拼起来假装一个对象覆盖完整。每事实核验疾病/字段/原值/来源，去重分配E编号。渲染上下文当时限12,000字，必要资料截断则停止。规则程序决定后续动作，不能宣传为模型每轮重规划；字段齐全也不等于医学充分性。

响应retrieval.agent含动作、观察、证据、次数、耗时及停止原因；验收脚本可temp保存完整工具返回后离线重放。未加账号库轨迹字段或长期日志。普通聊天仍隐藏来源；此时回答还用10消息窗口，正式整合后改变。

## 4. 第二次review：用户将展示标准改为技术深度

用户指出“能用”不足以体现Agent实习项目。原27重新审查：已有工具白名单、来源、超时/预算、反馈与轨迹是Harness底座；模型只理解一次，后续规则决定；历史存储+10消息不等于任务/会话记忆；资料字段覆盖不等于最终断言有证据。

建议按真实失败和可评测任务推进，而不按框架名称堆功能：

1. 动态Planning与任务工作记忆：后续对象依赖关系工具结果，模型根据观察选择合法动作；同工具/预算保留规则和单次计划对照。
2. 会话状态与上下文工程：保存有效目标/要求来源，支持更正、取消、话题失效和预算内选择；不预设跨会话画像或向量记忆。
3. 断言—证据验证：先校验引用/对象，再另行标注语义支持，不能把模型自评当医学审核。后续只实现了有限引用检查，没有完成全语义审核。

决定先冻结多步挑战和协议再实现，演示收尾移到验证之后；医疗项目展示标准升级，但Mini SWE Agent主项目方向未取消。外部依据当时核对Anthropic关于workflow/agent、上下文工程和eval的官方文章，属于工程取舍参考，非强制引入SDK。
