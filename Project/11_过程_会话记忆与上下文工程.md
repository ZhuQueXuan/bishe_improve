# 过程｜会话记忆与上下文工程

覆盖原36～38，过程2026-10-04，2026-10-05合并。顺序为教程对照→确认窗口缺口→带来源状态→离线对照→真实同预算检查。这里是独立合成会话实验；后续正式整合见[12](12_过程_正式整合验收与项目讲解.md)。

## 1. 教程对照带来的具体问题

用户提供[Hello-Agents](https://datawhalechina.github.io/hello-agents/#/)，要求对照第八章记忆/检索、第九章上下文工程，并明确不要可运行演示。原36当时阅读官方Markdown：

- [第八章](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter8/%E7%AC%AC%E5%85%AB%E7%AB%A0%20%E8%AE%B0%E5%BF%86%E4%B8%8E%E6%A3%80%E7%B4%A2.md)：写入、读取、更新、遗忘及不同记忆职责。
- [第九章](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter9/%E7%AC%AC%E4%B9%9D%E7%AB%A0%20%E4%B8%8A%E4%B8%8B%E6%96%87%E5%B7%A5%E7%A8%8B.md)：收集、选择、组织、压缩和按需访问。

这只是保留当时参考来源，不是本轮重新浏览或核验最新教程。项目已有RAG、任务状态/checkpoint和规划上下文白名单，缺的是会话目标/要求的更正、取消、失效与选择。没有理由安装整个教程框架、向量库、NoteTool/终端或多Agent；用户停用向量的决定不变。

首要方向变为可评测的会话状态与ContextBuilder，先查窗口是否真丢信息，再开发。长期画像、语义回忆、医学答案审核与模型保留题泛化仍另有范围，不一起扩张。

## 2. 冻结合成会话并维护有效状态

[conversation_context_v1](../bishe/data/conversation_context_v1/README.md)有8会话、开发4/预留4、tasks/oracle分离和哈希。作者见过所有题，预留一次执行不称盲测。开发前确认C02早期对象/要求超过10消息；C08原窗口约37,445字节超1,800预算，属于输入可得性缺口，不冒称实际用户故障。

conversation_context只处理显式“讨论/改查、只查预防、表格、取消、换话题”。对象表八病名是实验给定，不是通用医学实体识别。只本会话user更新状态，每值含source_message_id、version、topic、active；更正替代旧值，取消留空值及来源，换话题清旧目标/要求；助手提及不升级为用户事实。外会话先过滤，同ID同内容幂等，同ID改内容拒绝，须新消息表达更正。

只投影当前问题+有效结构状态/来源ID，旧原消息不整体重注入，避免同一消息已取消的要求复活。完整UTF-8字节硬预算，必需信息放不下context_limit且空payload，不静默截半状态。ceil(bytes/3)仅估算token；真实usage另统计。无LLM摘要、向量排序、长期存储、TTL或此模块跨进程恢复，不把任务checkpoint能力套到会话模块。

代码：[conversation_context.py](../bishe/knowledge_graph_backend/api/conversation_context.py)。新增12测试→145，覆盖更新/来源/预算/隔离，内存库和阻断网络，无真实模型/图谱访问/账号历史操作。

## 3. 离线对照先证明信息是否保留

A是预算匹配最近10条代理：按会话过滤，整条丢最早消息直到预算内；不是正式API原样。B累计结构状态。同预算/提取语法，模拟读取器仅能看到序列化payload，运行后再读oracle。

| 会话 | 检查 | 离线A/B | 真实A/B |
| --- | --- | --- | --- |
| C01开发 | 短追问 | 通过/通过 | 失败/通过 |
| C02开发 | 早要求出窗口 | 失败/通过 | 失败/通过 |
| C03开发 | 更正对象，保留要求 | 通过/通过 | 失败/通过 |
| C04开发 | 取消字段/表格 | 通过/通过 | 通过/通过 |
| C05预留 | 新主题、多对象歧义 | 澄清/澄清 | 澄清/澄清 |
| C06预留 | 助手提及不更新用户 | 通过/通过 | 失败/通过 |
| C07预留 | 跨会话隔离 | 通过/通过 | 通过/通过 |
| C08预留 | 大量无关消息预算压力 | 失败/通过 | 失败/通过 |

离线A6/8、B8/8，开发/预留各3/4对4/4；总payload4,122对3,770字节。C08 A丢了要求反而只有291字节、B508，不能宣称每题少token。离线分数证明信息保留与程序行为，不是DeepSeek准确率。

## 4. 真实DeepSeek同预算读取

新增conversation_reader和独立账本，不改状态提取/题集。相同提示/Flash/temperature0/json_object/thinking disabled/300输出tokens/15秒/零重试；共同提示913字节也计预算。仅返回status、objects、field、format，严格键/枚举/重复键/数量一致性；没有医疗答案、工具动作或图谱查询。每会话×方案各一次，最多16次/1元授权，实际16次，全部usage结算、结束不补跑。新增8测试→153，16SDK模拟合同通过。

真实A3/8、B8/8；开发1/4对4/4、预留2/4对4/4。A失败含C01状态/对象数量不一致（未保存拒绝原文，不能猜具体值）、C02/C08要求已从输入丢失、C03更正误读、C06把助手病名计成对象。C07隔离是程序先过滤，不算模型自行隔离能力。不能把所有差异叫记忆遗忘。

## 5. 结论与随后改变的决定

这段支持有限显式合成场景先维护有来源有效状态，再输入模型；A/B比较的是整个上下文方案，不是模型变聪明或纯因子消融，不报医学质量/真实用户泛化/长期记忆完成。原JSON和正式账号库哈希不变，零Neo4j访问/写入、无下载/配置/服务变更。

原38下一步只讲解，并没有接正式聊天；后来用户要求整合所有已实现机制，再最终讲解。正式历史重建、消息上限、来源实体检查、输入预算及恢复身份绑定是在[12](12_过程_正式整合验收与项目讲解.md)接入与单独验收，不能用本实验8/8代替正式API成绩。
