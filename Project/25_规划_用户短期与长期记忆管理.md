# 用户短期与长期记忆管理规划

日期：2026-10-23。状态：供讨论的建议方案，尚未实施或确定最终范围。依据当前源码核对；本轮没有修改业务代码、数据库、配置或调用模型。

后续用户同意推进，已实现[26第一版](26_过程_用户记忆管理第一版.md)：当前记忆查看/重置、有限手动长期偏好与问答接线。下文是完整候选规划，健康自述、自由文本、自动提取、过期复核等未实现，不将规划全部列为已完成。

## 目标与已有基础

希望用户在当前聊天里不用反复说明对象和要求；新开聊天后，可继续使用自己愿意长期保存的信息，并能查看、纠正、暂停使用和忘记。记忆的作用是帮助理解用户需求和选择表达方式，医学知识仍由图谱与专业文档提供。

现有`api/conversation_context.py`、`api/chat_runtime.py`已提供带消息来源的结构化会话状态：讨论对象、预防限定、表格要求，以及取消、更正、换话题。每次从当前会话用户历史重建，助手内容不能升级为用户状态；当前语法支持有限，不是通用自然语言记忆。登录聊天原文由`Conversation`/`ChatMessage`保存，按账号过滤；聊天历史持久化不等于跨会话记忆。游客历史主要保留在本次页面状态。

现有任务checkpoint用于短时间继续同一任务，沿用原截止和预算，不适合作为长期用户记忆。现有状态最多12000字节，最终输入总上限24000字节；后续接记忆仍须计算在总预算内。

## 建议的用户体验

聊天旁增加“记忆”入口，分当前会话与长期记忆两个区域。

| 区域 | 保存什么 | 建议操作 |
| --- | --- | --- |
| 当前会话 | 本次讨论对象、有效要求、取消/更正记录；后续可增加带来源的待办和上下文摘要 | 查看来源、修改/取消要求、重置当前记忆 |
| 长期记忆 | 明确选择长期保存的表达偏好、学习背景和关注主题；健康自述独立归类 | 新增、查看来源/更新时间、编辑、暂停使用、单条忘记、关闭跨会话使用 |
| 本次使用记录 | 哪些记忆实际被选入回答上下文，以及选择原因 | 显示“本次使用了哪些记忆”；与医学资料出处分开展示 |

示例：用户保存“我在学护理，解释时先说通俗含义，再解释术语”。新开聊天仍可沿用；当前说“这次只要简短结论”，本次要求优先，不自动覆盖长期偏好。一次讨论糖尿病只形成当前话题，不能自动成为“用户患糖尿病”。用户主动要求记住家属健康自述时，需明确记录家属对象，不能归到本人。

“重置当前记忆”保留聊天原文，但旧要求不得在下一问重新从历史重建。实现需有重置边界/版本，只从边界后的用户消息推导；旧任务恢复令牌也要失效，防止恢复时带回旧状态。不是仅清空内存中的字典。

“忘记长期条目”应立即停止检索、缓存和上下文使用。忘记不自动删除聊天原文，界面需解释两者范围。旧聊天中的“记住”语句不能在忘记后自动重放再创建；来源事件需幂等并记录失效版本。历史中已经生成的答案不追溯改写。

## 记忆内容和写入规则

第一版建议只在用户明确点击保存/主动新增时写长期记忆；自然语言“记住……”可先生成待确认卡片。不给每条聊天额外调用一次模型做提取，不自动遍历旧聊天建立画像。

每条至少保存：所属账号、类型、内容、涉及对象、来源会话/消息、用户确认方式、创建/更新时间、状态和版本、可选复核/到期时间。用户手动添加的条目记录手动来源，不伪造原消息。编辑产生新版本，避免旧值继续使用；同一次请求重复提交不重复保存。

医学相关记忆只表示“用户曾如此描述”，不能视为核验诊断，不能升级为图谱或医学引用。本人、家属、案例、假设必须区分；过敏、用药、检查结果等会变化的信息应独立标记时间和复核状态，不依赖旧记忆给个体处方。第一版不主动推断病史，不保存模型从问答中猜出的疾病。

过期或存在冲突的自述不默默选一个当成现状：停止自动使用并提示核实。具体保存期限尚待确定；展示偏好与健康自述不宜共用一个固定期限。

## 读取、冲突和上下文

建议流程：验证账号和会话归属 → 重建当前有效会话状态 → 读取该账号允许且未失效的相关记忆 → 处理本次更正/冲突 → 限量组装上下文 → 运行既有图谱/文档问答 → 返回实际使用记录。

- 当前用户明确要求优先于会话旧状态和长期表达偏好；临时要求只影响当前范围，长期更新须明确保存。
- 健康事实不简单套用“新的一定正确”：矛盾时保留来源和时间，必要时询问；不能把别人或假设案例的描述覆盖到本人。
- 助手输出、PDF内容、检索片段不能自行写入用户记忆；记忆内容也不能执行系统命令、扩大工具权限或跳过医学证据要求。
- 不把整个用户档案发给模型。首版按类型、主题、时间和状态筛选，设置条数/字节上限；总量包含在既有24000字节预算。超预算先减少可选长期记忆，不挤掉当前明确要求，不静默丢失关键冲突。
- 用户记忆与医学证据在提示中分区。用户记忆用单独标识，不能冒用医学E编号；网页的资料出处仍指向真实资料。

## 存储建议

先沿用现有Django/SQLite栈，用独立表保存长期条目、设置、版本/失效记录和会话重置边界，按登录账号严格过滤。结构化偏好和少量自述可直接查询，首版不需要新增数据库、安装记忆框架或调用embedding。

若后续实测发现大量自由文本经历无法按结构字段找到，再评估个人记忆的语义检索。届时可考虑既有Qdrant的独立collection；必须与公共医学文档隔离，服务端校验用户权限、状态与版本，不能只凭向量相似度或前端传来的user_id。遗忘和停用需同步派生索引；这不纳入首版实施。

如实施需要新增表，先备份当前账号库、检查迁移/回退方式，在临时或内存数据库验证；不把正式账号历史作为测试数据。本轮仅规划，未运行迁移。

## 分阶段实施与验收

1. **当前记忆可见与可重置。** 展示现有对象/要求及来源，实现重置边界；验证取消、更正、切换会话、重启后不会复活旧要求，任务恢复不绕过重置。
2. **手动长期记忆与管理。** 先支持表达偏好/学习背景；登录后跨会话复用，可编辑、停用、忘记。健康自述扩展明确对象/时效/确认机制后再接入。不改原医学库。
3. **受控读入正式问答。** 限量选择、冲突处理、当前要求优先、展示实际使用记录；游客不开长期记忆，切换账号清缓存，其他账号即使猜中条目ID也不能访问。关闭使用与停止收集分开说明。
4. **按证据决定增强。** 长对话摘要、自动记忆候选、语义检索均后置。摘要是可追溯压缩结果，不能自动升级为长期健康事实；若加入模型摘要，需限定触发阈值、用量和失败回退。

在实现前固定一组独立合成场景，覆盖跨会话记住偏好、临时覆盖、本人/家属、假设/否定、事实更正、到期、忘记不复活、关闭使用、跨账号攻击、助手/文档污染、并发编辑、预算和取消恢复。使用未参与规则编写的表达做留出检查，开发与留出结果分开报告。

对照至少包含“现有会话状态”和“会话状态+长期记忆”；比较真正需要跨会话信息的完成度、不该使用记忆时的误用、过期/错对象、忘记是否有效，以及输入token和额外调用。不能只展示成功回忆，也不能用新增离线检查数替代模型实际效果。先零费用验证生命周期/隔离，再用少量合成场景真实检查，原RAG首次结果保留。

建议先完成前两阶段的小版本，再接入正式回答和比较；暂不扩展为自动健康档案系统。
