# 用户记忆管理第一版

日期：2026-10-23。承接[25记忆规划](25_规划_用户短期与长期记忆管理.md)，用户同意继续后完成第一版，并已加载本机8000/8080服务。本轮没有真实模型调用，没有操作Docker或图谱进程。

## 如何使用

打开[聊天页面](http://127.0.0.1:8080/)，点顶部“记忆管理”。

- 当前会话：查看讨论对象、资料范围、表格要求及来源消息ID。重置保留聊天原文，从边界后的用户消息重新理解；可在聊天中用既有取消/更正语法调整要求。
- 登录后的长期记忆：主动选择解释方式、回答篇幅和学习背景，支持修改、停用/启用、忘记单条，以及关闭所有长期记忆的使用。刷新和新会话保留账号下的选择。
- 长期偏好实际进入当次回答时，回答下显示“本次使用的长期记忆”。本轮该使用记录只随实时响应保留，刷新后历史消息未恢复该记录；不能据此声称历史回答未用记忆。
- 游客只有当前页面中的会话记忆，没有长期条目。重置后页面过滤旧历史、切换会话代次并清除继续按钮；刷新仍按原游客设计清空。

第一版是用户主动保存的有限选项，不支持自由文本记忆、自动识别“记住……”、健康自述或个人病历。旧聊天中的提问、助手回答、PDF内容均不会自动写入长期记忆。无需新装数据库或记忆框架，不产生记忆embedding费用。

## 实现

后端新增`api/user_memory.py`和`api/memory_views.py`。SQLite新增`MemorySettings`、`UserMemory`，以及Conversation的`memory_after_id`、`memory_version`。长期条目按账号/类型唯一，修改带版本检查；相同内容和版本重复提交不重复增版，旧请求不能复活已忘记的条目。忘记清空数据库该条value并停止使用，保留类型/版本失效记录；不删除聊天原文，也不承诺清除旧答案、备份或已经发送的模型输入。

长期偏好只影响回答表达，不改变检索对象、医学E编号、证据和工具权限。后端从登录账号读取至多3条有效选择，转换为固定描述后放入回答上下文，不使用前端自报的user_id或任意文字。总输入仍受24000字节上限约束；可选偏好放不下时不加入，返回使用列表为空。当前问题及有效会话要求优先，这条生成行为尚只有模拟模型输入核验，未用真实模型比较遵循率。

重置通过消息ID边界持久化，不靠清空显示；历史重建只读边界后的消息。登录任务恢复的owner同时绑定会话记忆代次和长期设置版本，变更后旧令牌不再匹配。请求在检索后、回答后和保存前检查版本，若已变更则返回409，不保存旧回答；已发出的外部请求无法撤回。它不是通用的底层网络取消机制。

游客代次由页面维护；没有新增服务端游客身份或全局撤销登记。页面会清除旧按钮并换session_id，但主动保留旧guest身份与有效令牌的客户端仍可能在原短期限内重放。不能把页面重置宣传为所有游客令牌的服务端撤销。

前端新增`MemoryManager.vue`，接入当前`ChatWorkspace.vue`，更新chat store的游客历史边界和账号切换时的响应隔离。旧账号的迟到问答、新建会话、加载历史不会写入新账号界面；面板切换账号/会话会清空旧数据显示并忽略迟到结果。保存/停用等操作失败会给出提示，不伪报成功。
