# 会话要求的有效范围与撤销

日期：2026-10-24。承接[30模块审计](30_分析_模块完成度与记忆冲突处理.md)。用户同意先完善上下文管理中的会话状态，本轮完成代码、离线回归、隔离HTTP及本机正式游客检查，已重新加载8000后端。前端未改，8080已有服务HTTP200。

## 用户可使用的行为

| 表达例子 | 生效范围与结果 |
| --- | --- |
| “这次用表格”“本次只查预防”“这次简短点” | 仅影响当前回答；下一个用户轮次恢复仍然有效的原设置 |
| “接下来都用表格”“本会话简短点” | 本会话持续有效，显式换话题后仍保留 |
| “这个话题简短点” | 当前话题有效，换话题后结束 |
| 不带范围的“用表格”“只查预防” | 沿用原有话题范围；明确换话题或取消时结束 |
| 不带范围的直接篇幅/解释方式要求 | 本轮覆盖，不自动成为账号长期默认 |
| “换个话题”“换一个话题”“我们聊点别的”“说点别的”“请换个主题” | 清除旧话题要求和对象；保留明确的会话要求，重新识别当前明确对象 |
| “这次不用表格” | 暂时覆盖持续的表格要求；下一轮恢复原要求 |
| “取消表格要求”“取消只查预防”“取消篇幅要求” | 清除对应会话/话题覆盖；长期偏好继续按原有效设置使用 |
| “取消刚才的要求”“撤销上次的要求” | 撤销最近一组会话要求，恢复之前仍有效的设置；不复活已到期的临时要求 |
| “以后都简短点”“以后详细解释” | 继续使用已有有限长期偏好接线；本次采用新要求，是否持久保存仍受账号收集开关控制 |

“取消刚才的要求”目前只撤销最近一组会话要求，不是任意多级撤销。上一组涉及明确长期默认时，回复请用户明确要改成什么或忘记哪项偏好，保留原账号记录；不会猜测恢复哪个历史长期值。没有可撤销的会话要求时明确说明。

本轮没有给格式/检索字段新增账号长期存储。对它们说“以后”会限定为本会话；账号长期值继续只有解释方式、篇幅、学习背景。普通“改查某病”仍属于对象更正，不自动等同于换话题。

## 实现

新增`api/requirements.py`，把有限表达识别和要求生命周期放在同一个无数据库、无模型的模块中。每条有效要求记录值、作用范围、来源消息、原文片段、话题和轮次；同轮多子句按顺序生效。当前轮次覆盖高于持续设置，话题与会话设置按最新明确要求选择。临时覆盖到期后可恢复原来源，取消则保留必要的失效状态。

生产`ChatMemory`通过`SessionMemory`新增的少量钩子接入分层状态。旧`SessionMemory`默认的实验语法保持，历史窗口/结构状态试验没有重算成绩。正式上下文仍保留原`objects/field/format`输出结构，额外携带当前有效要求及来源；没有数据库结构变更或新的模型调用。

`effective_presentation`与生产状态使用同一套范围规则，将会话要求、本轮要求与账号默认组合后送入回答上下文。关闭自动收集时，明确当前要求仍可影响本次回答，但不写成长期默认。纯设置命令本地确认，不触发检索或回答模型；“详细解释一下”“说得通俗一点”等既有实质追问继续走对话衔接路径。

`dialogue_context`的历史话题分界与状态共用同一个判断，设置命令不重新作为旧问题摘要带入。摘取缓存版本改为`dialogue-extractive-v4-scoped`，旧v3结果保留原位，读取时不复用为新缓存。回答提示明确只采用当前有效状态及已选择偏好。状态12KB、最终完整messages 24KB、原次数/截止时间保护保持。

## 仍保留的限制和后续

- 仍为明确表达的有限规则，不能承诺任意口语、复杂嵌套条件、长距离作用范围或所有否定表达都理解正确。引用、假设等已识别情况保守不提取，不是通用语义分类器。
- “这次”按当前用户轮次处理；单独发送临时设置会得到本地确认，不承诺自动延长到下一个实质问题。
- 本轮没有实现本人/家属、健康事件时间、康复状态或健康信息长期记忆，也没有通用正文忠实度核验。
- 当前新版本没有追加真实模型遵循率或完整在线医疗问答复测。局部状态/输入正确不等于回答中的每句话都正确。
- 旧RAG和记忆试验的代码快照保持历史含义。后续使用当前代码做真实比较，应另冻结新身份/清单，不能修改旧哈希使其通过。

下一模块先讨论健康状态与记忆冲突的具体边界，再做会话内主体/时间/有效性处理；跨会话健康信息收集另定。RAG证据相关性与正文支持核验按30的后续顺序推进。
