## 一、要达到的结果

让系统能够在有限范围内完成五件事：记住值得保存的信息，区分用户要求和用户自述，发现新旧信息的关系，仅在相关时使用记忆，以及让失效或被遗忘的信息停止影响回答。

典型使用效果：

- “以后解释通俗一点”跨会话生效；“这次简短点”只影响本轮。
- “我妈妈有某种疾病”不会写成本人的情况。
- “上周感冒，现在那次已经好了”保留过去事件，但不继续当作当前状态。
- “以前喜欢甜咖啡，现在戒糖”分别表达口味偏好和当前选择，不能错误合并成“不喜欢甜”。
- 用户可以问过去的信息，也可以明确更正、停用或忘记；后台整理和旧摘要不能让失效内容复活。
- 多步查询保留任务进度、已取得证据和预算，使用哪些用户记忆可以在次级入口核对。

这是实习项目中的可运行、可解释、可评价的工程能力。第一版不承诺理解任意口语、不保证医学事实正确，也不扩展为完整电子病历、诊断或处方系统。

## 三、总体结构

```text
用户新消息
  ├─ 当前会话：当前问题、近期必要原文、有效要求、必要摘要
  ├─ 记忆处理：识别候选 → 检查原文/主体/时间/范围 → 判断新增或更新
  │                                  ├─ 明确要求：即时处理
  │                                  └─ 普通候选：轮次/话题触发整理
  └─ 记忆选择：账号/主体/状态过滤 → 相关候选 → 排序 → 预算选择
                              ↓
                 有效个人上下文（用户自述/偏好）
                              +
                 当次专业资料证据（图谱/文档）
                              +
                 工作记忆（任务步骤/待办/证据/预算）
                              ↓
                    回答及可核对的来源记录

后台维护：去重、关联、摘要更新、失效/遗忘传播、索引与缓存一致性
```

个人记忆说明“用户说过什么”，专业资料说明“回答依据是什么”，任务状态说明“这项任务做到哪里”。三者允许组合使用，保留不同来源与权限。数据库保存长期条目不等于每次全部放入模型输入。

## 五、A阶段：统一记忆表示与冲突规则

### 1. 记忆类型

第一版区分：

- 表达偏好：篇幅、解释方式等。
- 背景事实：例如用户主动说明的学习背景。
- 有时间的用户自述事件：例如某次不适及后续报告的变化。
- 用户当前约束或选择：例如本次要求、某段时间的饮食选择。

工作记忆沿用独立任务状态，不存为用户个人事实。医学指南不存为用户记忆，助手推断不自动转成用户自述。

### 2. 最小信息结构

| 字段组 | 含义 |
| --- | --- |
| 身份与主体 | 账号/会话归属、条目ID、本人/明确家属/未知主体；“母亲”可作为关系标签，第一版不解决同关系多人实体识别 |
| 类型与内容 | 偏好、背景、事件、约束；明确属性和值，避免把一整段聊天当成一个不可修改的事实 |
| 来源 | 用户消息ID、原文片段及定位；自由抽取结果必须能回到原文核对 |
| 时间 | 记录时间与事件时间分开；“上周”等原话保留，无法可靠转换时标明未知，不猜日期 |
| 有效范围 | 本轮、当前话题、当前会话、长期；事件的发生/结束时间独立表示 |
| 状态 | 有效、历史、已被更正、用户报告已结束、待确认、停用、已忘记等按类型限定，不能混用病情状态与存储状态 |
| 关系与版本 | 版本号、被哪条信息更正、属于哪个事件、相关但不同的偏好/约束；保留必要来源链 |
| 使用依据 | 明确要求/一般自述/待确认，不编造未经校准的置信度百分数；重要性类别与选择原因可解释 |

### 3. 更新决策表

| 关系 | 默认决策 |
| --- | --- |
| 同主体同属性，用户明确更正旧表达 | 更新当前有效值，旧值退出默认使用；保留更正关系 |
| 同一事件状态发生变化 | 更新事件的当前状态，保留发生记录；“用户报告已结束”不等于医学确认 |
| 临时要求与长期默认不同 | 只覆盖指定范围，到期恢复仍有效的默认 |
| 不同主体、不同事件或不同属性 | 分开保存，不强行合并；同一病名不能单独证明是同一次事件 |
| 可以同时成立的偏好和约束 | 并存；按当前约束选择行为，不改写原偏好 |
| 明确矛盾但没有足够时间/纠错依据 | 暂不覆盖；仅在影响当前回答时询问必要澄清 |
| 提问、假设、引用、助手推断 | 不直接建立本人事实；可用于理解当前问题 |

退出A阶段的标准是语义和数据边界一致，不是先堆很多正则表达式。明确规则作为可解释基线；复杂表达若需要模型抽取，作为单独可比较路径，不让模型直接任意写库。

## 六、B阶段：先在当前聊天内证明规则有效

范围：从本会话原始用户消息重建有限状态，区分本人/明确家属、过去/现在/未知、否认/更正/用户报告结束。只把与当前问题相关的状态加入回答上下文，旧助手答案不作为病历或专业证据。

处理示例：

1. “我没有糖尿病，想了解高血压”不应把被否定疾病混入当前查询目标。
2. “上周感冒，今天那次已经好了，现在咳嗽”不自动认定新症状由旧事件引起，也不自动把旧事件算作进行中。
3. “我妈妈有高血压”不能变为本人患病；“已经好了”涉及多人或多事件时不猜。
4. “好一点了”“还没完全好”不能等同于事件已结束。
5. 用户明确回顾过去时，允许读取历史状态，不因其不再当前有效而无法查询。

验收应覆盖真实APIView的对象选择、检索问题、实际送入回答的状态，以及重置/跨账号隔离。模块状态正确与最终模型措辞正确分别验收。

## 七、C阶段：渐进建立长期记忆

### 1. 写入路径

- 即时路径：已有有限偏好的“以后”“更正”“忘记”等受支持表达沿原路径处理。C首版健康“记住”先生成来源候选，用户在设置确认后才提交，并回报实际结果。关闭对应收集、没有登录或持久写入失败时，不能虚假回复“已经长期记住”。
- 候选路径：对普通对话按轮次/话题触发整理，提取结构化候选，核对来源、主体、时间、已有条目关系后提交；不等用户关闭页面才唯一触发。
- 后台路径：归并、去重及维护由后续F阶段承接。生成式提取先做少量显式触发，验证后再允许后台使用，不隐藏无限调用。

去重按事件身份和属性判断，不单凭句子相似度合并。提交使用版本检查、原子操作和稳定事件ID；处理重试或重复消息时不重复写入，不能将已忘记条目重放恢复。

### 2. 接入范围

优先保留已有三类偏好，补充A阶段确定的有限结构化背景/事实和用户明确要求保存的事件。一般聊天中的健康自述第一版先停留在会话内；长期健康事件先采用用户明确要求保存或明确确认候选的方式，界面不逐条打扰所有普通对话。

C首版已按有限范围实施，见[36](36_过程_受控长期疾病自述与跨会话使用.md)：仅本人单个已知疾病及状态，默认关闭独立健康保存开关，明确命令后还需确认。家属、过敏原、药物及自由文本档案尚未支持。更广泛的自动健康收集、上传病历、药物/剂量推断和完整健康画像不在第一版。后续若要改变收集方式，先明确类型、用户开关及可验证行为。

### 3. 存储与管理

优先使用现有SQLite技术增量扩展，保留旧偏好接口与数据；复杂事件单独结构，不强改原有限值字段来容纳任意文本。迁移先副本、后备份，原账号/聊天逐表内容核对。用户仍通过次级设置查看、纠正、停用、忘记，正常回答不展示冗长内部过程。

退出C阶段至少完成：同账号新会话读取、不同账号隔离、使用/收集开关、即时更新与版本冲突、来源核验、重复处理、暂停/遗忘不复活、写入失败诚实反馈。

## 八、D阶段：个人记忆检索

推荐流程：

1. 过滤账号、主体、允许类型和条目状态；确定问题问的是当前还是过去。
2. 偏好或精确属性先结构读取；事件描述采用关键词候选，保留各自来源。按用户2026-10-26决定，个人记忆语义向量召回延后到整个框架完成后评估，不作为D的实现或验收要求。
3. 在允许候选内综合相关性、类型化新近程度、重要性，必要时去重和控制同类占比。
4. 按输入预算选择，记录选入/排除原因；无相关记忆则不硬凑。

本轮D先评价结构查询和关键词选取的命中、漏召回与误带入，记录后续优化的基线。框架完成后，再考虑关键词与向量候选并集，检查是否真正补足同义召回；不直接照搬专业文档检索方案。精确少量偏好无需向量化。

时间与重要性是可解释因素，不是万能加权公式。历史问题应匹配对应时间；稳定偏好和重要健康自述不因年代久远或少被检索就自动失效。重要信息也不能在所有无关问题中占据输入。第一版先给类型化规则，再用对照数据调整权重，不能预先声称最优。

框架完成后的向量待办可复用现有Qdrant/embedding适配经验，评估独立个人记忆集合、严格账号过滤及来源/版本校验；专业文档集合保持独立。嵌入内容、外发范围、费用和用户选择届时明确，首次用合成记忆离线/受控验证。向量异常应能回退结构/关键词检索，不能跨账号回退。本段为后续评估约束，尚未实施或授权外发个人信息。

## 九、E阶段：摘要和输入预算

三层内容：近期必要原文、较早话题的可回查摘要、按需读取的长期条目。摘要和长期记忆有独立准入条件，不把“太长被压缩”自动当成“值得长期保存”。

先保留已有摘取方法作基线；再比较结构化摘要，必要时才增加模型摘要。摘要覆盖ID、原文来源、生成版本和记忆修订号都要记录。更正/忘记后旧摘要失效，重新生成不能从已排除来源恢复旧事实。

必须核对：主体、事件时间、否定词、不确定性、关键数值和单位、限定条件及更新关系。摘要无法保住这些信息时保留必要原文或说明缺失，不能用猜测补齐。短期不实现任意病历压缩或所有医学细节高保真保证。

现有12KB状态和24KB完整messages保护先保持，新增内容在同一预算内分配。只有经过明确评估才调整上限，不能通过调大窗口掩盖失效记忆大量带入的问题。

## 十、F阶段：整理与遗忘闭环

区分五种动作：本次不选入、当前状态失效、降权、归档、用户要求忘记。采用逻辑状态与范围明确的维护任务，保留必要版本和重放防护。

- 后台任务具有ID、版本、状态、有限重试和去重；重启不能重复覆盖新状态，旧任务不得在用户遗忘后提交旧结果。
- 只按类别清理：短期任务缓存可到期，历史事件可归档；长期未检索不能直接推出已康复、已失效或应删除。
- 遗忘使条目、派生摘要、缓存和向量结果停止使用；明确区分“忘记提取的记忆”与“删除原聊天”。保留聊天时，候选提取必须尊重排除标记，不能重新提取复活。
- 用户新消息重新明确表达，与旧消息重放区分；是否允许重新记住按用户开关和命令范围处理。
- 物理清理另按项目文件规则执行：不得批量/递归删除；若清理必须批量删除文件，由用户手动处理。逻辑失效与查询排除不依赖批量文件删除。

第一版后台维护是项目内部有限任务，不创建新的Codex定时任务，不默认安装队列集群或启动持续付费整理。

## 十一、G阶段：工作记忆、界面和整体评价

工作记忆先核对现有能力，补选用记忆ID/版本、查询步骤、待办、证据和费用归属。暂停恢复仍受原任务范围与预算约束；用户记忆变化后，旧暂停任务不能静默使用过时上下文。长期断点恢复、任意任务调度不是本轮默认扩展。

界面继续收敛：正常聊天自然使用，次级设置支持查看及纠错；需要澄清时说明具体冲突，不展示原始协议字段。后台写入或索引失败有状态，不能仅因任务完成就显示“记忆已保存且可用”。

评价贯穿各阶段，G负责组合核验：

| 维度 | 核对内容 |
| --- | --- |
| 提取/写入 | 原文支持、主体准确、类型正确、应记/不应记、重复写入、更新关系 |
| 冲突与时间 | 临时覆盖、历史/当前、兼容信息不误合并、该澄清时澄清、不必要打断 |
| 检索 | 相关项命中、无关项带入、历史问题、失效内容、跨账号泄漏与重要项误排除 |
| 摘要 | 关键事实保留、来源可回查、遗漏可见、没有新增用户未说的信息 |
| 生命周期 | 遗忘传播、旧消息/旧任务重放、重启、版本竞态、缓存和索引一致性 |
| 最终回答 | 使用有效要求、正确主体/时间、不把记忆当医学依据、答案主张有专业来源支持 |
| 成本与体验 | 外部请求次数、tokens/费用、延迟、失败原因、澄清次数；不把零调用快速返回直接当检索更快 |

比较建议：相同题目/专业来源/模型参数下，对照已有有限偏好版本与新模块；必要时增加不使用个人记忆组。合成场景先行，真实模型另建具体小批计划和新冻结身份；不重用旧批余额、旧响应或旧代码清单。

开发可见题与留出题分开；由同一个助手编写并检查不称独立盲测或医学审核。工程回归通过、模型任务表现、医学适用性分别报告。第一版核心约束场景要求逐项通过，其他效果报实际分项结果，不捏造总体准确率。
