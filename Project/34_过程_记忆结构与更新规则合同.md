# A阶段：记忆结构与更新规则合同

日期：2026-10-24。依赖[33阶段0](33_过程_记忆阶段0基线整理.md)已完成，落实[32框架](32_规划_分层记忆系统与逐模块实施框架.md)中A阶段。当前完成的是可运行的独立记录校验和决策规则，没有接入聊天或持久化。

## 完成内容

新增`api/memory_contract.py`，仅提供两个无副作用函数：

- `validate_record`：核验结构、字段类型、取值、来源片段、账号/会话归属和时间结构，返回独立副本。
- `decide_update`：在两条已经结构化的候选之间给出新增、并存、暂时覆盖、替换有效值、事件变化、澄清或拒绝等决定；不修改输入，不写数据库/摘要/索引。

这份合同让后续模块使用同一套基本概念。B阶段负责自然语言理解及来源含义核验；C负责权限、版本和真实持久化；D—F负责选择、摘要及遗忘传播。不能因为这里返回`forget`就称已把所有派生数据删除，也不能因为返回`event_transition`就称理解了用户的健康变化。

## 字段定义

| 字段 | 第一版语义 |
| --- | --- |
| `id/owner/session/revision` | 独立记录身份、账号/来源会话与版本；不可通过复用同ID改写内容；决定中保留被更新版本，后续写入仍需原子检查 |
| `subject` | 本人、`family:关系`或未知；只是关系标签，不保证现实中同关系多人的实体消歧 |
| `kind` | 表达偏好、背景、用户自述事件、约束四类 |
| `attribute/value` | 受处理的属性与已提取值；语义由后续抽取器证明，合同本身不把相似文本当同一属性 |
| `scope/scope_ref` | 本轮、当前话题、会话、长期；当前轮/话题/会话具有对应作用范围标识 |
| `storage_state` | 有效、停用、被替代、被忘记；与事件状态独立 |
| `event_state/event_id` | 非事件不填事件ID；事件区分当前、过去、用户报告结束、否认和未确定；ID用于表达已建立的同一次事件关联 |
| `recorded_at` | 与来源消息一致的带时区记录时间，不能当成事件时间；更早来源不能静默覆盖更新记录 |
| `event_time` | 时间原话与可选起止时间；原话应出现在来源片段中，无法可靠规范化则保留null，不猜日期 |
| `source` | 用户消息ID、Unicode字符半开区间、完全对应的原文和表达类型；账号/会话必须与可信来源消息一致 |

只校验原文跨度的身份，不代表验证了`subject/value/source.mode/event_id/intent`的含义。比如“以后详细点”被错误抽成brief，只要原文跨度仍一致，纯结构校验无法发现。专门保留了这个反例测试，防止后续将来源校验包装为通用语义正确性。

记录时间必须带时区，与来源消息一致；事件时间规范化格式和区间可以校验，但“上周”具体对应哪个日期仍需B阶段的时间规则和原文证据，不能由格式正确推断理解正确。

## 更新规则

| 情况 | 独立规则的输出 |
| --- | --- |
| 没有已有条目，来源与结构合格 | 新增候选；来源表达为问题/假设/引用/助手推断则拒绝 |
| 长期详细与本轮简短 | 临时覆盖，不修改长期默认 |
| 明确新默认或纠错、同主体同属性 | 替换当前有效值的建议；保留旧来源，后续存储处理历史关系 |
| 本人与家属，或偏好与不同属性的当前约束 | 分开；不能把“喜欢甜但戒糖”变成“不喜欢甜” |
| 更晚消息描述历史，而非当前 | 保持历史与当前记录独立，不按新记录时间决定事件先后 |
| 同名但不同事件ID | 分开，不能按病名合并 |
| 已建立同一事件ID，且有明确变化意图 | 给出事件变化建议；仅为用户报告，不产生医学确认 |
| 事件ID未知/不一致、更新主体未知、值不同但缺少更新依据 | 澄清 |
| 不同账号、原文不符、字段非法、遗忘后的旧来源重放 | 拒绝或结构异常，不生成写入 |
| 原记录停用/被替代/忘记，新的不同来源再次表达 | 暂不自动启用，交由后续明确的生命周期政策处理 |

需要明确意图的决定要求候选已被识别为`explicit_request`；这个标记及`intent`必须由后续模块核验，传入标记不是语义证明。不同会话的临时状态不会互相覆盖；本模块也不处理实际开关授权、自由文本医疗写入或后台并发提交。

## 验收

实现前先写入`contract.json`和`acceptance.json`，固定20个开发可见结构化场景（A01—A20）。随后18项独立测试检查这些场景和结构、时间、来源、幂等及无副作用等约束。全量结果为原379+新18＝397项全部通过；原来源/预算19项通过。早期16项小范围结果保留，不与最终全量重复计数。

检查包括：原文跨度损坏、中文字符与UTF-8字节位置混淆、跨账号来源、助手来源、类型错误、无时区时间、记录时间伪造、倒序事件区间、未知主体、明确纠错与含糊更新、不同事件/作用范围、遗忘重放、停用不静默重启，以及决定不修改输入。

这20个场景输入是已经结构化的候选，不是20段原始自然语言被系统正确理解的结果。尚未进行B阶段提取、真实模型、临床、盲测、浏览器或完整问答评价。
