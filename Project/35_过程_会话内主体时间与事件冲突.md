# B阶段：当前会话的主体、时间与事件冲突

日期：2026-10-25。承接[32阶段计划](32_规划_分层记忆系统与逐模块实施框架.md)和[34结构合同](34_过程_记忆结构与更新规则合同.md)。本轮完成有限明确表达的会话内处理，已接入正式聊天并加载本机后端；没有开启跨会话健康记忆。

## 用户可见的变化

| 对话例子 | 现在的受限行为 |
| --- | --- |
| “我有糖尿病”“我妈妈有糖尿病” | 本人和母亲分开，不合并为本人病史 |
| “我上周感冒了”→“我那次感冒已经好了，现在咳嗽” | 将有来源的旧事件更新为用户报告已结束，新查询围绕咳嗽，不把旧感冒一并作为当前查询对象 |
| “我没有糖尿病，想了解高血压” | 从检索与回答问题中移出被否定的糖尿病，保留高血压问题 |
| “好转了”“没有完全康复” | 不认定已结束；保留为未确定的用户报告状态 |
| “我有糖尿病”→“我没有糖尿病” | 存在实质矛盾时先澄清，不直接用消息新旧决定覆盖 |
| “更正，我没有糖尿病” | 同主体、同属性的明确纠错形成更新；原聊天和来源保留 |
| 本人和家属都提到感冒，之后说“感冒好了” | 不根据最后提到的人猜测，先确认是谁的情况 |
| “我去年感冒了”与“我今天又感冒了” | 分别记录事件；回顾去年时选匹配的历史事件，不只返回当前值 |
| “我不是没有糖尿病” | 多层否定先澄清，不直接记成否认 |
| 无关知识问题、新会话或当前会话重置 | 不默认带入无关或其他会话的个人自述 |

只有报告变化、没有可回答的明确查询时，可以本地确认或澄清，不调用理解、检索或回答模型。纯当前自述可继续进入原知识查询路径；不能据此称系统已进行诊断。

这些行为只覆盖本轮限定的明确句式和已知疾病名称。不能从以上例子推广为任意病史、任意口语或医学推理能力。

## 1. 实现方式与A阶段接线

新增`api/session_health.py`。它从本会话用户原话提取有限候选，记录主体、疾病属性、事件状态、时间原话、来源消息及字符跨度。候选经A的`validate_record`核验；有更新关系时使用`decide_update`，在内存中形成当前有效报告、冲突候选和审计关系。

没有直接恢复阶段0已归档的`health_context.py`或其测试。旧草稿仍位于`temp/memory_phase0_20261024_7069ddeb2b/`，原失败与旧31项结果保持历史含义。新模块的语法准入、事件关联、时间及A合同接线均另行核查。

普通肯定/否定自述、过去自述、用户报告结束以及不确定/好转状态分别表达。提问、假设、引用、学习或希望康复等表达，不直接形成本人患病报告。识别到一个子句涉及多人、多疾病或多层否定时，采用必要澄清。未匹配语法的句子不自动建立健康事实，但仍可能作为原有资料查询的文字进入既有路径。

因此“不提取”不是完整医学意图或敏感信息分类器。B本轮不实现任意药物、过敏原、检查数值或自由文本病历的完整结构化。

## 2. 事件关联、时间和主体

- 同病名本身不能证明同一次事件。首次报告形成局部事件身份；有“那次/这次”等明确指代，或当前话题内同主体唯一的具名结束报告且没有冲突时间，才建立状态更新关联。
- 新的明确时间或“又/再次”等表示新一次的表达保持独立。原先当前事件未给时间，后来报告去年已结束，也不能擅自结束原当前事件。
- “现在好了”主要表达状态变化，不能只因“现在”就新建一次患病。若“上周那次”与先前“今天”的事件时间冲突，则先确认关联。
- 现实人物只支持明确的本人及若干家属关系标签；“母亲”不是现实世界统一人物ID，不解决同关系多人的完整实体消歧。跨主体纠错不静默搬移旧记录。
- 原记录、明确更新及关联理由保留，选入上下文的辅助旧记录明确标成追溯依据，不作为当前有效状态。

登录历史使用数据库中真实消息时间；游客历史或内部调用缺少可靠原消息时间时，`recorded_at`仅表示本次重建记录的时间，另标`reconstruction_time_original_message_time_unknown`。它不是过去消息的真实发送时间，也不是事件发生时间。

“上周/去年/现在”等事件时间原话单独保留，起止日期仍为null。本轮不做日历日期推算，不把带绝对年份而未明确当前的报告直接判为当前状态（保守设为未确定）。没有基于时间流逝自动康复、到期或降权。

历史回顾按明确时间原话匹配事件，并可沿同事件的后续自述追溯已结束状态；同一时间范围匹配多次时需要澄清。不是通用时间推理或任意自然语言日期解析。

## 3. 正式问答与来源边界

`ChatMemory`在原状态/范围规则之后接有限会话报告，`ChatAgent`在工具调用前处理相关冲突和纯状态更新。只有确实过滤了被否定/已结束内容，才替换相应的检索与回答问题；普通指代分支保留原来的回答接口约定，避免阶段0复现的两个旧回归再次出现。

健康状态包标记`current_conversation_only`和`user_reports_not_medical_evidence`。每条候选既校验A的来源映射，也再次对照会话保存的原始用户消息检查字符跨度，不能只修改中间来源注册表来伪造引用。助手消息不能更新用户自述状态。

只在当前问题涉及相应主体/疾病或明确回顾时选择相关报告。一般知识问题不因同病名就假设用户患病，无关主题不为旧自述占用上下文。当前有效状态、冲突候选及必要追溯原文具有不同用途；用户自述不能代替当次专业图谱/文档证据。

原12KB必需状态和最终完整messages 24KB保护保持；超过状态预算整包停止，不静默丢失必要健康状态。来源绑定跨度过长时请求拆分，避免合法长消息导致未处理异常。

## 4. 历史引用、缓存、并发和暂停

已经识别的旧报告子句不再作为近期对话或旧问题摘要重新带入；保留同一消息中的实际问题，纯报告之后的助手确认/旧推断也不作为新引用依据。该过滤只针对已识别报告，不是通用正文语义擦除或所有历史内容的全面核验。

摘取缓存版本升级为`dialogue-extractive-v5-session-reports`，旧缓存不复用；不把新健康记录结构写到`Conversation.context_notes`或`UserMemory`。原聊天仍照既有行为保存，后续请求从当前会话有效历史重建。关闭/重置会话的既有账号隔离规则保持。

加入两处状态过时保护：

1. 登录会话在回答生成期间新增了消息，原请求在返回/落库前检测到历史游标变化，返回409并丢弃旧结果，不写入这条过时助手回答。无法由此撤回已经在途的提供商请求或保证零费用。
2. 暂停令牌的所属上下文绑定自述内容签名，报告变化后旧任务不能继续。签名不使用临时消息ID或重建时间，因此消息落库后从临时ID变成数据库ID，不会误判为自述已改变；恢复仍沿用原任务预算，不重开90秒。

游客状态来自本次提交的历史，不承诺对所有旧游客历史/令牌做全局服务端撤销。更通用的工作记忆和长期任务机制仍留在G阶段。
