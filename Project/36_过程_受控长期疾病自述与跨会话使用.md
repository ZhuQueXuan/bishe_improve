# C阶段：受控长期疾病自述与跨会话使用

日期：2026-10-26。承接[32持续计划](32_规划_分层记忆系统与逐模块实施框架.md)及[35会话内处理](35_过程_会话内主体时间与事件冲突.md)。本轮完成有限类型的受控写入、管理及精确跨会话读取，并加载本机后端。一般个人记忆检索仍留D阶段。

## 1. 用户如何使用

1. 登录，在账号的“记忆设置”打开“允许确认保存本人疾病自述”。开关默认关闭；原偏好自动收集开关与它分别控制。
2. 在聊天中明确说“记住，我有糖尿病”或“请记住，我上周感冒了”。系统只准备候选，并明确回复尚未长期保存。
3. 打开记忆设置，核对原话，点击“确认保存”。可以点“不保存”；候选十分钟后失效。保存失败会显示错误，不报成功。
4. 新建同账号聊天，明确问“我的糖尿病有什么相关资料？”时，可读取相应的已确认自述，作为个人背景。专业答案仍必须依靠当次医疗资料。
5. 更正时重新说“记住，我没有糖尿病”，核对后选择更新具体原条目。确属另一次经历时选择“保存为另一次事件”。设置中也可停用、启用或忘记。

关闭“在回答中使用长期记忆”会阻止选用，保留存储。关闭健康保存开关会阻止新候选和待确认提交，已确认条目仍按使用开关处理。“忘记这条自述”清空该提取条目，保留原聊天；不能通过旧确认或旧消息重试恢复。用户重新发送新的明确请求并确认，可以重新保存。

## 2. 本轮接入范围和取舍

支持B阶段可识别的、本人、单个已知疾病名称的明确自述，保留当前/过去/用户报告已结束/否认/未确定状态及时间原话。记录时间来自实际聊天消息，不能当作发病时间；日期仍不做日历规范化，不因时间过去就认定康复。

健康长期收集默认关闭，而且所有健康条目都要用户确认。本轮未实现普通聊天自动提取、家属长期记录、过敏原、药物/剂量、上传病历、自由文本健康画像或生成式摘要。原有三类表达偏好与其接口保持。本人的日常健康自述继续按B在当前会话内理解。

截图中的“冲突就更新旧记忆”不能直接作为医疗项目规则。程序不会因新消息较晚就覆盖：当前明确自述与已存同名状态矛盾时，在工具和模型前澄清；用户在设置中选定条目并确认，才建立更新关系。不同明确时间/新一次的报告不自动当作纠错。同名多次经历的问题缺少时间时先问哪次，不能取列表第一条。

新内容采用独立的HealthMemory及HealthMemoryProposal，不向旧UserMemory的有限值字段塞自由文本。单账号最多保留50条未忘记条目；候选管理只展示最近20条有效候选。不是无限个人档案。

开源评估核对了[Mem0仓库](https://github.com/mem0ai/mem0)、[近期发布](https://github.com/mem0ai/mem0/releases)和[LangGraph源码包配置](https://github.com/langchain-ai/langgraph/blob/main/libs/langgraph/pyproject.toml)。Mem0使用Apache-2.0，LangGraph使用MIT；两者有持续维护记录，可作为后续参考。当前是Django/SQLite内的有限确认与版本事务，迁入整套记忆/编排框架需要重接用户权限、来源和已有聊天接口，现阶段收益不足，因此复用已有技术栈与A/B纯函数，不新增框架依赖、模型或服务。

## 3. 来源、事务、更新和重放

候选只来自这次明确命令，不扫描旧聊天。用户、会话、稳定客户端消息标识形成幂等键；内容哈希不一致时拒绝，同一命令重试不生成重复聊天或重复候选。关闭开关或不合格的请求也保留处理回执，因此后来打开开关不能把旧拒绝请求重放成新保存。

候选保存消息引用，不复制一份健康报告。确认时重新读取实际用户消息，校验账号/角色、原文哈希、会话重置边界、候选期限和个人记忆版本，然后用B语法重新解析、A合同核验原文跨度及字段。用户不能在确认API里提交任意疾病、主体、状态或来源。

同名条目必须明确选择更新目标及版本，或确认另一次事件。更新保留事件身份，经过A的decide_update明确纠错决定；新版本替换有效报告。旧来源保留于原聊天及提交回执，不把矛盾旧值混入当前答案。本轮没有完整历史版本浏览器；不能将原聊天留证称为任意版本回滚功能。

确认、条目生命周期及个人记忆版本变更在事务内；版本变化使旧候选不能再覆盖新状态。SQLite并发写入锁冲突按失败返回，事务回滚，不承诺分布式事务或多机写入。重复确认返回当前结果，不再次写入或启用已停用/忘记的条目。

停用保留内容；忘记清空report并保留最小身份/版本/回执防重放。旧的“记住……”命令及其助手确认从后续对话引用中排除，摘要缓存升级v6，状态更新也清空该账号缓存，避免从原保存命令重建已忘记条目。原普通聊天的当前会话自述仍有B自己的范围；本轮不声称任意语义来源、所有派生物的全面遗忘闭环，F阶段继续完善。

## 4. 读取和回答的边界

C只接精确的个人问题：明确本人措辞、明确疾病名称、账号使用开关打开、条目active、来源可核验。一般知识问题、“我想了解……”和家属问题不默认带入本人记录。同名多事件优先按明确时间原话匹配，没有唯一目标则澄清。普通指代、新会话里只说“它”、同义词召回和跨类型排序尚未实现，属于D。

来源被删除或语义字段不再与原文一致时停止选用。删除原会话后，条目可能仍显示在设置里，但不能作为已核验背景选入；需要用户重新整理。本轮不把数据库内部被篡改等同于有完整防篡改安全体系。

当前会话明确报告优先作为当次状态，但不会改写长期库。相关健康条目与会话状态共用12KB必需状态上限，在工具前检查；最终仍受原完整messages 24KB及90秒保护。健康记录不是专业E来源，不能增加医学依据数量，也不能授权工具动作。

保存/停用/忘记或使用设置改变会增加个人版本，旧在途回答在返回/落库前被现有版本校验停止；暂停令牌所属会话也绑定该版本。已经在途的外部请求无法撤回，不能由此保证零费用。
