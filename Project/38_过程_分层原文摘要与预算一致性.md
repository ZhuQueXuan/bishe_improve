# E阶段：分层原文摘要与预算一致性

日期：2026-10-26。承接[32持续计划](32_规划_分层记忆系统与逐模块实施框架.md)与[37个人检索](37_过程_个人记忆结构检索与时间选择.md)。本轮完成有限词面识别的结构化原文摘取、必要原文保留、缓存来源核验与预算覆盖一致性，并加载本机。没有使用模型生成摘要，个人向量接入仍在D—G之后。

## 1. 用户可见变化

以前摘要会从一条消息中只留下较长的问题。例如“我妈妈昨天空腹血糖是5.6 mmol/L，还不确定，想了解这个数值如何理解”，可能只留下最后的提问，丢失数值的主体与限定。

现在对有限识别范围内的必要信息保留完整连续原话，并标记主体、时间、数字、单位、否定、不确定性及假设/引用。它们是对原话的词面标注，不是医疗事实提取、确诊或完整病历。正常聊天无需新开关。

- 较早原话仍可按有限项目词进入必要引用；例如后续明确追问“空腹血糖这个数值如何理解”。
- 明确同主体、同项目、同时间原话的更正会排除旧引用及其助手解释。当前这一问就进行完整更正时，也在工具前排除旧引用。
- “更正，应该是6.1，不是5.6”缺少明确关联时先请求补全，不推断是谁、什么项目或单位。
- 相关必要原文无法完整放入预算时，请用户缩小问题或分条说明；不截断数字、否定后继续回答。
- 旧格式要求即使出现在引用原话中，也不能替代当前有效要求；已取消表格等仍以原状态为准。

本轮没有扩展长期健康收集。家属、检查数值出现在本会话引用缓存中，不表示建立了家属或检查数据的长期健康条目。原C保存范围及默认关闭的健康收集开关保持。

| 层 | 内容与约束 |
| --- | --- |
| 近期/必要原文 | 近期最多6个合格片段；必要较早原话在摘要层放不下时可移至原文层，合计4800 UTF8字节 |
| 较早结构摘要 | 只摘取合格用户原文、来源与词面保护标记，最多6片段、1800字节；不摘要助手旧医学正文 |

旧6000字节触发阈值保留；有相关必要旧原文时也触发整理。非关键普通历史问题仍沿原摘取方法；助手近期正文仅作对话引用，清除旧E标记，不成为本次专业证据。

项目词有限支持空腹/餐后血糖、血糖、体温、血压、体重、身高、心率及若干常用数字/单位。词面标注不能识别所有医学数值、用药记录、语义否定或人物关系，不支持完整病历高保真压缩。数值和单位逐字保留不代表系统能判断其医学意义。

本轮先核对了[LangMem摘要源码](https://github.com/langchain-ai/langmem/blob/main/src/langmem/short_term/summarization.py)、[README](https://github.com/langchain-ai/langmem/blob/main/README.md)及此前已核验的[MIT许可](https://github.com/langchain-ai/langmem/blob/main/LICENSE)。源码提供触发阈值和运行摘要，但生成摘要依赖模型，直接接入还需适配本项目原文跨度、账号修订、医疗边界和预算。此次采用阈值分层思路，继续已有SQLite和纯函数；不安装框架或增加付费模型依赖。公开源码可查不代表已独立保证上游维护质量。

## 3. 来源与更正

用户引用保存原消息ID、Unicode字符起止、完整原消息SHA256及会话partition。B已经过滤后的问题只能映射回允许的原文片段，不能为了补全来源恢复被B排除的病情报告。无法映射则排除并标记，不假造引用。

缓存不作为可信输入源。每次从当前可用原文重建规范条目，仅在版本v8、修订号、会话partition、有效状态及完整规范条目相同的情况下统计来源复用。修改缓存文字、角色、偏移或保护标记无法改变本次生成的引用。原消息其他部分改动也会使其来源哈希变化，即使提问片段文字相同。

更正处理为有限规则：明确同一主体标签、项目词和时间原话，且只有一个先前候选时，记录`correction_link`并排除旧引用及相关助手解释；并不宣称验证现实世界同一事件。缺乏这些条件时，不合并新旧数字，必要时先澄清。假设/引用中的“更正”不应替换真实旧原话。时间原话相同也不等于通用日期归一或现实事件身份证明，本轮仍受有限句式边界约束。

本次问题中的完整更正由原任务问题保留，结构中只存被排除旧来源的关系，不把本次问题伪装成已有数据库消息。多次明确更正按尚有效候选递进，不能重新取回更早旧值。

## 4. 预算、遗漏与缓存一致性

原12KB状态和最终24KB完整messages上限、90秒与调用预算保持。结构来源元数据也占同一预算，未通过扩大窗口隐藏问题。

层内优先保留相关关键原话，可选近期助手引用/旧普通问题按预算退出。进入12KB状态包时只能裁剪可选条目；如果必要原文与状态合计超限，停止并提示拆分。没有必要引用而只剩可选元数据超限时，可省略整个可选引用包；覆盖ID为空并报告原因，不拒绝本来可完成的普通问答。

裁剪后ChatAgent使用实际入包的`dialogue_bundle`，返回给前端的覆盖ID、保存在`Conversation.context_notes`的内容及实际模型输入一致。遗漏按原因计数并显示最多6个来源ID样例，避免长对话的遗漏清单本身耗尽上下文。旧原文仍在聊天中，遗漏不是删除。

更正/缓存修订后旧条目不从缓存复活。重置保留原聊天、重新建立边界；C/D保存命令与回顾回答的排除仍生效，已忘记健康条目不会经这些旧回顾转存为摘要。通用的跨派生物遗忘、后台整理和排除任务仍由F继续，不能称E已实现完整遗忘系统。
