# 工作记忆绑定与组合验收

日期：2026-10-26。承接[32分层记忆框架](32_规划_分层记忆系统与逐模块实施框架.md)的G阶段，以及[39整理与遗忘](39_过程_记忆整理任务与遗忘来源闭环.md)。

本轮完成**有限工作记忆补强、组合工程验收和本机加载**。原0—F的有限实现保留，G现在把选用记忆、任务步骤、待办、来源证据和调用归属一起固定。真实模型的最终措辞、医学适用性、浏览器实际点击和独立留出题效果仍未验收，不能把本轮结果写成整个记忆系统的准确率。

## 1. 用户能看到的变化

选择“先看关联结果”，输入原先支持的多步资料问题，例如“我的糖尿病的并发疾病中，选前2个，列出描述和预防资料。这次简短点。”，随后在剩余时间内点击“继续整理”。

- 继续沿用原查询选中的本人长期自述，以及“这次简短”等临时要求。临时要求不会因此改成长期默认。
- 如果用户已经更新、归档或忘记相关记忆，重置会话，或者插入另一条实质用户消息，原暂停结果停止，需重新提问。不会悄悄用新状态续做旧任务。
- “查看本次整理依据”可核对累计规划/回答次数、本次新增查询、待处理字段数、已取得出处及健康自述ID/版本。正常回答不铺开内部协议。
- 缺少有效usage或计价依据时，保留未知；界面写“费用尚未计算”，不会把缺失费用写成0。

仍只支持原有一个疾病起点、并发关系排序可见最多8项中选前2项、描述/预防字段的资料整理。暂停仍是原90秒任务内的短时保存，不是长时间自主运行或通用任务平台。

## 2. 本轮确认并修复的缺口

1. F时的健康选择按当前请求计算。“继续整理”没有原问题的个人指向，恢复查询进度后可能漏掉原来选中的长期健康自述。
2. F时表达选择在恢复请求重新计算，原问题的本轮要求可能到期，从“这次简短”退回长期详细默认。
3. 原PlanningHarness检查文件中的无密钥SHA256及重建证据，但该状态文件的精确内容没有被聊天签名绑定。改写剩余截止并重算本地校验值可能通过。G把状态文件SHA256放入签名覆盖的metadata，并在实际读取恢复字节时再次校验，拒绝改写状态、计数和到期时间。

旧F文件未覆盖。用同样三个开发可见场景在独立进程中加载冻结F的chat_runtime/views，三处均复现；当前G三处均通过。该对照不代表未知问题效果或医学质量。

## 3. 实现与来源边界

新增`api/working_memory.py`；修改`chat_runtime.py/views.py/planning_runtime.py`及原页面的次级依据区。没有新依赖、数据库模型或迁移，没有扩大健康采集类型。

任务绑定记录个人版本、会话版本、健康条目ID/版本/完整选择来源指纹、原账号偏好、实际表达选项和用户输入链指纹。签名覆盖原问题、有效会话packet、dialogue引用、绑定信息、累计调用回执和原进度字节哈希。metadata预览只做校验，不消耗任务。

恢复时：

1. 校验签名、账号/会话/自述语义归属、文件大小和精确哈希，拒绝已占用令牌。
2. 用**原始选择问题**重新读取允许的个人记忆，并比较绑定；保存病名指代展开前的原问题，避免展开后丢失个人选择依据。
3. 重核已冻结的dialogue来源消息哈希，核对用户输入链；原自述、原话或相关偏好被改动时停止。
4. 重建并校验原工具观察、实体、证据、待办和累计次数；原截止时间不延长。一次原子占用防止两个请求重复花费同一暂停预算。
5. 使用原packet和dialogue，继续剩余步骤。恢复词“继续”不会把无关旧长记录重新提升为必要上下文。

健康自述仍标记“用户自述，非医学证据”，不进入E专业出处编号；个人记忆不会指挥工具或改变资料权限。暂停的`selected_memory`表示任务选择，尚无最终回答时`used_health`保持空；回答真正附加后才报告使用。恢复后实际模型packet、dialogue覆盖和缓存使用同一冻结内容。

原5读/4规划/1回答/90秒不变。多次暂停保留累计和本次新增次数；缺项/失败反馈仍由原Harness处理。每次已计费规划动作均有task_id/序号/角色回执，缺失usage也留占位；回答失败的一次尝试同样记账，不自动重试。只保留规范token计数，不复制SDK错误正文或健康原文到回执。未实现价格计算，cost为null。

新聊天任务合同版本拒绝旧的短时checkpoint；不恢复旧版本令牌或重开预算。检查点仍存本机temp，签名不等于加密；未新增长期轨迹库、跨机器调度、常驻worker或自动清理。

因此0—G的**已约定有限工程阶段**已逐项执行；规划中的通用口味/约束收集、历史偏好版本查询、任意语义理解、生成式总结与独立真实效果仍是明确缺口，不能写成完整健康画像或所有核心自然语言场景已完成。
