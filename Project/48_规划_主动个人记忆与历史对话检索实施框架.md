## 一 目标场景与实施边界

贯穿场景：第一次聊天用户说“我有高血压”，在开启相应主动记忆范围后，系统保存为“本人明确自述有高血压”，保留原话、日期和来源，不补造诊断依据。另一次聊天用户问“这款药适合我吗”，即使没有重提高血压，也应读取与问题有关的有效背景；有关键冲突则先核对。回答展示采用了哪条个人背景，专业药品依据另行检索。

这一目标验证的是背景获取与使用流程。现有医学图谱和六份专业资料不能被描述为完整药品禁忌或相互作用数据库。本阶段不实现自动处方、剂量推荐或临床安全判断；集成用药场景先用虚构药名和人工设定的资料验证接线，真实适用性能力另立范围。

拟定第一版主动发现范围：本人的明确疾病自述、过敏或不耐受自述、明确当前用药、明确阶段状态，以及与服务有关的长期表达偏好和背景。症状、测量与检查结果按事件保存，不自动升级为诊断。上述新增类型均需逐类定义字段和测试后再开放，不把已有HealthMemory直接泛化为任何健康档案。

不自动记作本人事实：普通提问、假设、引用、助手的推测、家属描述、临时回答要求，以及无关身份信息、密码和验证码。家属自动记忆、上传病历解析、模糊药名归一、自动推断剂量及完整健康画像放在后续范围。

## 二 保存和检索的整体结构

```text
新消息或用户选定的旧聊天
  → 核对账号、开关、允许范围和来源排除
  → 提取候选及原文依据
  → 判断补充、变化、更正、新事件或冲突
  → 业务数据库提交记忆版本，并登记索引任务
  → 后台生成向量 → 独立个人集合 → 核对版本后标记就绪

当前问题
  → 处理本轮明确更正与临时要求
  → 重要背景结构读取 + 按需关键词和向量召回
  → 回原记录核对账号、主体、时间、版本、状态及原文
  → 选择有限相关上下文 + 独立专业资料证据
  → 生成回答并提供个人来源入口
```

本轮已只读核对现有Conversation、ChatMessage、MemorySettings、UserMemory、HealthMemory、候选/来源排除/维护任务，以及memory_retrieval.py、document_vectors.py和embedding.py。现有长期偏好是有限值，HealthMemory的语义是已确认的有限本人自述；不得把历史确认状态批量改成自动推断，或将新自动记录标成“用户已逐条确认”。

| 层次 | 拟保存内容 | 职责与边界 |
| --- | --- | --- |
| 原聊天 | 消息、角色、会话、发送时间 | 沿用原库；旧话是历史依据，助手文字不成为用户事实 |
| 记忆当前版本与历史 | 内容、类型、主体、断言程度、事件关系、来源、版本、有效状态 | 业务库是使用资格的最终依据；保留用户更正，遗忘内容停止使用 |
| 历史片段 | 同话题必要相邻消息、说话者、来源跨度、摘要及原文校验 | 不把整场聊天压成一个向量；摘要不能替代原文 |
| 个人记忆向量 | 简短检索文本的向量、用户ID、记忆ID及版本等 | 拟新建个人记忆集合，不写现有专业文档集合 |
| 历史对话向量 | 允许检索片段的向量及对应来源标识 | 拟另一历史片段集合，区别于当前个人事实 |
| 同步任务 | 目标版本、内容哈希、尝试次数、租约、结果 | 与业务写入事务登记，有限重试，可观察失败及重建进度 |

记录时间至少区分：消息发送时间、事件发生或适用时间、提取入库时间。自动发现旧话时不能用今天的入库时间决定其比昨天的自述更新。未说明的事件时间保持未知；疾病自述、疑似和否认分别保存，不能只靠一个“置信分数”替代。

## 三 按顺序实施和验收

每步先完成其必要回归和隔离验证再进入下一步，不为每次微小改动新建测试项目。优先扩展已有测试文件；阶段失败保留首次结果，修复结果另行记录。以下通过标准是计划，不是现有成绩。

### P00 固定范围与现有基线

**做什么：** 整理原版本实际可用能力和已知限制，固定待支持类型、来源字段和数据流。区分主动发现新消息、检索旧会话、从旧会话补提取三项权限。设计第一版分开的收集、使用及历史范围选择；原auto_enabled=true不能默认等于同意新健康收集或全历史外发。建立合成多账号聊天样本，先标注应记、不应记、应更新和应澄清的期望。

**怎么测试：** 在隔离环境复核已有关键记忆/来源/账号行为；逐条核对样本标签及当前D方法的选取结果，包含应当“不命中”的问题。记录当前源码、正式库及原专业集合的基线指纹，不将用户使用期间的正常变化恢复成旧字节。

**通过标准：** 明确现有与计划的区别；样本、范围、评价口径和旧方法结果已固定。未选择真实历史时零扫描、零外发。P00结束仍不写正式数据。

### P01 固定自动记忆和冲突规则

**做什么：** 按类型定义允许字段、自动保存条件、澄清条件和不保存条件；定义本人/家属、确定自述/疑似/否认、长期要求/临时要求。统一补充、同事件变化、新事件、明确纠正和待核对关系。

**怎么测试：** 用结构化输入验证规则表，涵盖“我有”“我可能有”“我爸有”“如果有”“这次简短”“刚才说错”；检查“近期血压正常”不会自动清除既往疾病自述，不同年份事件不会被合并。此处验证确定性决策，不冒充自然语言理解已通过。

**通过标准：** 固定规则案例全部满足期望；关键含义不清时不擅自选定用户事实。第一次实现先有规则合同，再接提取模型。

### P02 建立来源和版本化保存

**做什么：** 在现有业务库基础上设计增量字段或表，具体迁移方案届时确定。保留原账号、聊天、偏好及已确认自述。区分自动提取来源、用户确认状态、当前有效状态、争议状态和索引就绪状态。保存原文跨度/哈希、时间、事件ID、版本及更正关系。遗忘、停用和来源排除从这一阶段就参与读写资格核验。

**怎么测试：** 在合成库和数据库副本做迁移正反演练；断电式中断、重复请求、并发更新、旧版本提交、跨账号引用、原文修改及来源缺失。业务提交与索引任务登记要么共同成功，要么一起回滚。普通读取不得创建或确认记忆。

**通过标准：** 原表内容和原语义保持；重复提交不重复写、过期写入不覆盖新版本。无来源的提取不能进入有效记忆；未就绪向量不阻止有效结构信息使用。未来正式迁移前另备份当时受影响的数据；47的Docker大备份已按用户要求删除，不能当可恢复依据。

### P03 主动发现新聊天中的候选

**做什么：** 对新用户消息进行有界提取，结合必要相邻语境返回结构化候选和精确原文引用。明确规则处理常见命令，语言模型承担需要理解的提取部分；模型输出视为待校验数据，不能直接决定存储、账号权限或最终冲突处理。精确药名、数值单位和否定不由模型补全。先形成自动保存预览，再接开关控制的有效提交。

**怎么测试：** 离线回复替身覆盖非法字段、错误角色、伪造引文、同消息多事件、超长和中断。之后在单独允许的有限外部批次中，用虚构聊天检验同义表达、否定和指代；统计提取精确率、漏记、误记、原文支持率及澄清次数。失败调用不得回复“已记住”。

**通过标准：** 每个有效候选均有本人原话依据、类型和时间限定；固定负例不写入。真实语言能力必须有真实模型批次证据；只通过替身测试时状态仅为接线通过。是否采用额外模型调用、何时提取以及其费用上限在该步执行前明确，不自动继承已结束的旧批次。

### P04 接新旧信息更新和遗忘闭环

**做什么：** 将P01规则接到已验证候选。明确更正撤销错误归属，同事件变化更新当前状态，新事件保留独立身份；重复信息关联来源，不按重复次数提高事实权威性。关键冲突保留双方原话并提出具体问题，处理结束前不能把其中一方默认为确定事实。用户更正和遗忘优先于未完成后台提取。

**怎么测试：** 在多轮聊天中演练补充、停药、同名多次事件、先后时间乱序、旧聊天晚入库、用户纠正家属归属、泛化否认与具体过敏记录冲突。模拟两个窗口同时更正、提取任务晚完成、遗忘后重试以及旧回顾摘要再次出现。

**通过标准：** 不使用“最近入库必然正确”策略；临时要求不改长期偏好。明确纠正可更新，无需永久保留错误内容为当前事实；未解关键冲突必须带争议状态。已遗忘内容不能由原话重提取、摘要或旧任务复活；后台已生效结果提供可查看/撤销入口数据。

### P05 先做好结构和关键词检索

**做什么：** 给问题分配读取策略：一般知识默认不带个人病史；个人适用性问题主动读取相关类型的有效背景；历史回顾按事件和时间查询；少量表达偏好直接读取。重要背景不依赖向量Top-K才有资格进入候选。超过容量时主动缩小范围或核对缺口，不悄悄截掉关键背景。

**怎么测试：** 即使模拟向量无结果，“某药适合我吗”仍应读到符合资格的背景；“高血压是什么”不无关带入本人历史；问父亲不套用本人。覆盖当前/历史选择、未提病名、多个主题、未知时间、无人登录和关闭使用。

**通过标准：** 重要背景读取路径可独立工作；不命中不等于无病史，信息不完整不等于适用性已确定。固定选取案例全部符合期望且能解释选入/排除原因。本步结果作为后续向量收益的主要对照。

### P06 接独立个人向量索引与同步

**做什么：** 复用原Qdrant服务和底层接口经验，新建独立个人记忆集合。先用合成向量检验写读，再在允许范围内使用真实Embedding。固定模型、维度、输入格式及检索指令的配置标识。现有embedding.py查询指令专为医学指南检索，不直接复用于个人记忆；个人指令及配置单独设计，不覆盖专业集合。相同维度不代表不同模型向量可混用。

保存时先提交业务版本和索引任务，再后台处理；任务对账号、记忆ID、版本、内容哈希幂等。向量写入前后核对版本与使用资格。只有内容或嵌入配置改变才重算，元数据变化可单独同步。检索由后端绑定登录账号，并回业务库二次核验。

**怎么测试：** 隔离集合中验证账号过滤、遗漏过滤的拒绝、伪造用户ID、返回其他账号候选的拦截、错误模型/维度/配置、同版本重复任务、旧任务覆盖、写入后未标记成功、同步时更正/遗忘、超时、断线和重启恢复。断网后回退P05。新配置或重建不影响原134个专业点。

**通过标准：** 固定隔离与失效用例无越权使用、无旧版本回流；完成任务每次回读一致，重复执行不重复计费或无限重试。需记录真实用量和失败的不确定费用，不能把未知记为0。原专业资料、集合配置、向量与业务数据保持。

### P07 接历史对话切片和受控补提取

**做什么：** 对用户选定历史范围生成必要语境片段，另建历史索引。保留说话者、消息顺序、原文跨度、摘要版本和处理游标。先检索旧话，再按P03/P04规则选择性补充个人记忆；“搜索旧话”和“将旧话转成当前记忆”是不同操作。分批、增量、可暂停和继续，先预览范围，不默认扫描整个账号。

**怎么测试：** 多话题长会话、相邻否定/更正、重复切片、问答角色混合、提示注入、旧记录时间与入库时间倒置、源消息已删除或被排除、暂停后切换账号、处理中关闭权限。摘要丢失限定时拒绝或回原文，不靠向量猜测。

**通过标准：** 旧话可以定位原会话原文；不能从助手的话创建本人病史。当前状态由有效时间及后续更正核验，历史命中不能覆盖更新事实；被遗忘来源不会重建记忆。首版只处理选定小范围，不做全库自动回填。

### P08 将检索结果接入正式回答流程

**做什么：** 将结构、关键词、向量候选去重后核验，按当前问题选择有限上下文；个人自述与专业资料证据分开标注。相关背景及时影响检索问题和回答，而不是只存在管理页。保留当前完整messages预算和任务暂停机制；记忆版本变化使旧在途输出或旧续做失效。历史中的指令只作为被引用内容，不能改变系统权限。

**怎么测试：** 隔离真实HTTP与合成模型输入中核对最终送入内容，而非只看检索列表；覆盖无病名的个人适用性问题、跨会话、无关知识、资料不足、冲突、在途遗忘和暂停后更正。模型真实遵循另用虚构用户小批测试，区分提取成功、检索成功与回答正确引用三件事。

**通过标准：** 被撤销/未授权/别人的数据不进入模型上下文；重要背景和原话限定得到保留。个人记忆不当专业医学证据；系统不因记住病名就宣称真实药品安全。检索失败有清楚说明，不悄悄依赖过期缓存。

### P09 完成用户可控制的页面

**做什么：** 提供主动记忆范围、使用开关、历史选择、是否允许云端处理等清楚入口；展示自动/手动来源、时间、原话、待核对和同步失败。自动保存轻提示支持撤销；明确区分停用、忘记提取的记忆、删除聊天、撤销云端处理许可。关闭收集不应暗中更改已保存内容的使用选择。

**怎么测试：** 实际浏览器注册/登录的合成账号演练自动记录、跨会话参考、更正冲突、来源回看、撤销、遗忘、退出和切换账号、刷新、窄屏及网络失败。每次失败操作显示真实结果；云端许可关闭时检查无外发。浏览器禁用时保留未验，不绕过也不以HTTP代替点击成绩。

**通过标准：** 用户能看懂记了什么、为什么使用及如何纠正；权限变化在前端、后端和后台任务一致生效。实际点击证据和接口证据分别保存，不能仅凭构建成功交付为页面验收通过。

### P10 同题比较与本机版本收尾

**做什么：** 固定开发集和未参与调参的保留集；在相同允许语料与资源口径下比较：原D结构/有限关键词、主动记忆加结构/关键词、主动记忆加结构/关键词/向量。另用人工核对的相同记忆集合只比较后两者的检索，避免把提取差异误称为向量收益。

**怎么测试：** 运行受影响后端/前端回归、必要隔离HTTP、真实Qdrant读写及浏览器闭环；对实际异常安排必要修复回归，完成后才执行集中回归。模型或Embedding用虚构/明确允许资料，有限批次、失败留证，不重跑选优。模拟断线、索引落后、后台重启及更正/遗忘并发，做副本备份恢复检查。

**通过标准：** 固定权限/遗忘/来源/更正关键用例全部通过；抽取、召回和最终回答分别报告，所有失败保留。保留集若出现个人信息误记、跨账号使用或失效内容作为当前事实，修复前不启用自动模式。向量是否保留取决于相对P05的实际收益及成本，没有收益则维持结构/关键词并关闭可选向量。正式数据迁移和上线另按当时方案收尾，不自动发布或部署公网。

## 四 必须覆盖的贯穿场景

| 编号 | 场景 | 要验证的行为 |
| --- | --- | --- |
| T01 | 明确本人疾病自述，后续个人问题未提病名 | 自动发现并在相关场景结构读取，注明是自述 |
| T02 | 普通知识、假设、引用、家属或助手结论 | 不写成本人确定事实，不错误借用本人背景 |
| T03 | 疑似、否认、数值与单位 | 保留原限定，不推断诊断或补造剂量 |
| T04 | 同事件结束与同名新事件 | 更新和新增分清，历史仍可追溯 |
| T05 | 明确纠正“刚才说错了” | 撤销错误现状，原话和更正依据关联 |
| T06 | 近期观察与既往背景同时存在 | 不用观察替代历史，不擅自判定矛盾 |
| T07 | 新入库的三年前聊天与近期更正 | 依据来源及事件时间，不按入库时间覆盖 |
| T08 | 具体过敏记录与后续笼统否认 | 待核对并询问，避免任选一方作确定判断 |
| T09 | 忘记后重提取、旧摘要、旧向量及迟到任务 | 所有派生入口停止使用，保留聊天也不复活 |
| T10 | 伪造用户ID、退出、切换账号、跨账号片段 | 后端拒绝越权；查询过滤和回源核验均有效 |
| T11 | 云端权限关闭、Docker/Embedding失败 | 无未授权外发，结构查询可用，失败不冒称保存成功 |
| T12 | 近似说法找回旧事件 | 找到来源且判断当前适用性，不只追求相似分数 |
| T13 | 在途更正、遗忘与暂停继续 | 旧状态不继续生成或展示为有效结果 |
| T14 | 重复任务、旧版本和崩溃恢复 | 幂等、可定位失败、有界重试、无过期覆盖 |

评价记录：提取精确率与漏记率、原文支持率；关键背景遗漏、相关记忆召回、误带入、正确澄清及无结果行为；最终上下文是否符合资格；索引延迟、响应耗时、上下文字节或token、模型/Embedding用量与实际可知费用。样本少时报告逐例和分母，不宣称通用准确率。性能指标在P00固定本机基线和限额，不凭规划臆定提速倍数。

## 五 数据处理与开源复用决策

本机Qdrant保存向量不等于全部处理本地完成。云端提取模型、Embedding、最终回答分别有外发环节，摘要和查询也可能含个人信息。执行前需给出各环节允许的字段/文本范围、历史范围、次数、用量及费用上限；仅允许Embedding不代表允许把整场聊天送给提取或回答模型。先用虚构数据完成接线，真实个人内容未明确允许时不外发、不扫描，不要求用户提供密码或密钥到聊天。

| 方案 | 匹配情况与许可 | 本阶段取舍 |
| --- | --- | --- |
| [Qdrant](https://github.com/qdrant/qdrant) | 现有服务；[Apache 2.0](https://github.com/qdrant/qdrant/blob/master/LICENSE)；集合、过滤及混合查询可参考官方能力 | 复用现有部署及适配经验，新增个人集合；正式专业集合不变 |
| [Mem0](https://github.com/mem0ai/mem0) | 对话提取、去重和语义查询与需求相关；[Apache 2.0](https://github.com/mem0ai/mem0/blob/main/LICENSE) | 参考候选提取/检索，直接迁入需重接Django账号、来源、时间、更正和遗忘合同，成本较高；暂不整体替换 |
| [LangMem](https://github.com/langchain-ai/langmem) | 提供前台/后台记忆处理示例；[MIT](https://github.com/langchain-ai/langmem/blob/main/LICENSE)；常见示例使用LangGraph Store | 参考流程边界，整体迁移会引入额外Store接线，暂不引入框架 |

2026年10月27日已核对上述公开项目、文档及许可，仓库和文档均可访问；网页未提供足够信息确定全部版本的近期维护频率，不用Star数量推断成熟度。P00至P03选定具体依赖前，再检查对应版本、近期提交/发行、未解决问题及适配成本，固定所选版本；本轮无安装或依赖更换。Qdrant官方参考：[集合](https://qdrant.tech/documentation/manage-data/collections/)、[账号过滤示例](https://qdrant.tech/documentation/examples/multitenancy/)、[混合查询](https://qdrant.tech/documentation/search/hybrid-queries/)。新功能须以本机现有1.19.2支持为准，不照搬更新文档要求自动升级。

## 六 推进约定

本框架的P00至P10全部为待实施、待测试，不能将本轮文档核对记为功能通过。用户下一次明确要求开始实施时，从P00推进；当前“先别开发”期间不创建迁移、测试脚本、索引或后台任务，不切换开关，不重启服务，也不新增付费调用。

每阶段正式成果写在本项目Project目录，运行实现放bishe，实验/日志/临时副本放temp。沿用既有有界任务、预算、账号和来源保护；不扩大成另一个大型项目，不修改Mini SWE Agent主项目。32保留原阶段历史，48成为本次新方向的顺序入口；旧M06/偏好历史和邮箱页面验收不得顺手标成完成。
