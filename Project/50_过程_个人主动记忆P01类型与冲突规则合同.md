## 类型与字段

新模块复用原memory_contract.validate_record，检查来源消息所属账号、会话、用户角色、发送时间及原文跨度，返回独立副本；原A规则和原测试类保持。新增候选仅包含category、assertion、record、details四项，拒绝未知字段。当前十类为结构合同，不能称为已支持十类自然语言识别。

| 类型 | 可补充字段 | 限制 |
| --- | --- | --- |
| 疾病自述 | 无额外字段 | 病名须在来源中，明确自述、疑似、否认分别保留 |
| 过敏自述 | reaction | 与不耐受分开，反应必须在原话中 |
| 不耐受自述 | reaction | 不自动改成过敏 |
| 当前用药 | dose_raw、frequency_raw | 可缺省，但不能补造；有值须逐项对应原话 |
| 阶段健康状态 | 无额外字段 | 保留原状态和时间，不推断是否仍适用 |
| 症状事件 | 无额外字段 | 保留事件，不推断诊断 |
| 测量事件 | value_raw、unit必需 | 数值和单位原样支持，不临床解读 |
| 检查结果事件 | result_raw必需，unit可选 | 结果原样支持，不扩展病历解析 |
| 表达偏好 | 无额外字段 | 沿用已有style/length有限值 |
| 服务相关背景 | 无额外字段 | 第一版沿用已有background有限值 |

来源跨度匹配不能证明提取的语义。合同对category、subject、assertion、source.mode及intent依赖受信提取/调用适配器提供正确依据。专门保留一个反例测试：若外部错误地把假设标成本人肯定自述，纯结构校验不能发现全部语义错误；P03必须正确识别假设后，本规则才能拒绝。没有用形式校验冒充语言理解成功。

## 保存和冲突决策

调用者显式传入当前账号、逐类收集许可、是否来自旧聊天、选定历史会话及排除来源；候选不能自行声明这些权限。默认收集许可为空，旧auto_enabled不隐式授权新增类型。关闭收集仍允许针对准确目标的明确遗忘或停用。这里产生的是建议结果，不执行写入；P02/P04提交时仍需重新检查权限、来源及版本。

| 情况 | 合同决策 |
| --- | --- |
| 有许可的、可追溯本人自述或有限偏好 | add；不标为用户已确认或医学确认 |
| 疑似或否认 | 保留其断言程度，不能换成肯定自述 |
| 提问、假设、引用、助手推断、家属 | reject；主体不清则clarify |
| 临时要求 | temporary_only，不改变长期默认 |
| 不同信息，例如既往疾病与近期测量 | keep_separate，不用测量替代病史 |
| 已明确不同事件ID的两次同名事件 | keep_separate，不按新旧覆盖 |
| 同一次事件状态改变 | 目标ID/版本和事件关联齐全才event_transition，否则clarify |
| 明确纠正 | 必须有明确请求、当前目标及事件依据，replace_effective并要求后续保留历史 |
| 原信息补充字段 | supplement仅允许添加新字段，不能借补充删掉或替换旧值 |
| 新长期偏好 | 首次add；已有记录需明确请求与当前目标版本才能替换 |
| 旧聊天晚入库 | 以来源发送时间检查，不允许因晚入库覆盖更新来源 |
| 已排除来源、已排除目标来源、已遗忘重放 | reject；其他非活动目标先clarify，不静默复活 |

新旧冲突不按相似分数、提取置信度或最近入库时间决定胜者。同事件关联仍不清时先澄清。笼统“没有过敏”不能直接改掉具体药物过敏目标。家属归属更正需要后续撤销错误本人记录的专门操作，本步不会自动创建家属档案。没有实现基于自然语言的多候选关联，也没有用本步结果回填P00的2/9或13/16成绩。
