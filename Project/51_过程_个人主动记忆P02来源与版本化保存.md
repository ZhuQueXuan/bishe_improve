## 保存结构

| 新模型 | 作用 |
| --- | --- |
| PersonalMemoryPolicy | 独立逐类收集许可、选定旧会话范围、使用开关及版本；默认无收集且关闭使用，不继承旧auto_enabled |
| PersonalMemoryEntry | 账号下的32位不透明记忆键、当前版本及active/disputed/paused/forgotten状态 |
| PersonalMemoryRevision | 各版本候选、来源消息、完整消息哈希、会话版本、原发送时间、入库时间、前版本、来源方式、确认状态及索引状态 |
| PersonalMemoryReceipt | 同账号请求键、输入指纹和仅含ID/版本/动作的回执，关联来源和条目，防止重放及重复来源遗漏 |
| PersonalMemoryIndexTask | 与记忆事务一起登记的upsert/delete意图、目标版本、内容指纹和许可版本；本步没有执行器 |

九个原模型类与阶段前源码逐字比较保持；没有向原MemorySettings、偏好或已确认HealthMemory中塞入自动推断内容。新增记录始终区分自动来源和用户确认，不能由候选字段伪造“用户已确认”或“医学确认”。主体、原话限定和事件时间继续包含在P01候选中，消息发送时间与入库时间单独保存。

## 写入与读取规则

保存必须以当前登录账号对应的持久化用户消息为来源，核对角色、所有权、会话、原文跨度和发送时间，还要匹配提取时捕获的完整消息哈希及会话版本。即使被选原文跨度没有变化，外围语境已变也不能照常提交。重置游标和原来源排除同时参与核验。

收集许可和历史选择从数据库读取，调用者必须提供期望的当前许可版本；候选不能自行开启权限。当前/历史来源的调用上下文、语义含义及明确意图仍由后续受信适配器建立，本步不声称从任意文本自行证明这些含义。

事务先条件写入许可行取得数据库写入保护，再核对目标版本；SQLite不依赖无效果的select_for_update。条目版本递增采用版本和状态条件更新，条目、历史版本、索引任务、回执共同提交。数据库锁争用只返回静态冲突码，由调用方使用相同请求键重试，没有无限重试或日志泄露SQL/个人正文。

同请求键同输入只返回重放元数据，不再写入或返回旧个人文本，也不声称该条记忆现在可用；同键不同输入拒绝。相同有效内容不新造版本和任务，但关联本次来源到回执，后续遗忘也排除这些重复来源。不同事件新增条目，不覆盖原事件；更新则保留旧版本并令旧排队索引任务失效。

read_current不创建策略或记录，仅在使用开关打开、条目和版本有效且来源仍可核验时返回；返回前再核对许可及条目版本。索引pending不妨碍结构化读取。read_history仅返回版本和状态等管理元数据，不提供旧正文绕过当前资格。争议状态已具备读取拦截，但实际语义冲突如何登记和解除留待P04；本步的clarify结果不会自动变成有效记忆。

明确遗忘/停用是减少使用的管理动作：要求当前用户消息中有明确请求、精确本人目标和当前版本，即使收集关闭仍可执行。原来源失效后不伪造证据来修改临床内容，但允许用户遗忘目标；已停用目标也可继续遗忘。遗忘清除所有版本的提取正文，并排除全部关联来源，原聊天保留；同时登记删除索引意图。此处未接入旧聊天上下文和暂停状态的全链路失效通知，P04/P08还需完成，不能当成实时聊天遗忘闭环。
