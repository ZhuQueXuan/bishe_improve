## 当前支持的行为

| 用户表达 | 候选含义 |
| --- | --- |
| 我有高血压 | 本人自述，尚未由用户确认或医学核实 |
| 医生说我可能有高血压 | 不确定的自述，不升级为确诊 |
| 我没有高血压 | 否定自述；若已有相同属性，交P04处理，不旁边追加矛盾的有效记忆 |
| 我对虚构药甲过敏，反应是皮疹 | 逐字保留药名及反应，不补全其他过敏原 |
| 我目前服用虚构药丙，剂量0.5mg，频次每日2次 | 保留原名、剂量和频次原文，不推断医嘱 |
| 我今天测得血压135/85毫米汞柱 | 测量事件及原数字单位，不推断疾病 |
| 我昨天发烧了 | 原时间词及过去状态，日期归一化仍为空 |
| 以后请尽量通俗一点 | 有限长期表达偏好；本次临时要求不转成长期默认 |

十类P01类型均有有限句式支持，包括不耐受、临时健康状态、检查结果和学习背景。疾病名称仅高血压、糖尿病、哮喘、冠心病、慢性肾病五个明确标签；复杂药物组合、模糊指代和其他句式不能据此称已支持。药物与反应示例均为虚构工程数据。

## 提取与保存边界

`personal_memory_extraction.py`不访问数据库或网络。提取输入是带来源的当前用户消息；最多4096个UTF8字节、5个候选，不截短后继续猜测。每项由服务端构造账号、会话、不透明ID、原发送时间、事件ID及版本，精确跨度按Python Unicode字符下标定位。原文改变时完整消息哈希和候选ID随之改变。

家属、问题、假设、引用、敏感验证码/密码、拒绝记忆、明显更正和遗忘指令不会作为普通新记忆写入。分句后若出现未能解释的否定或不确定限定，例如“我有高血压。但我不确定”，整条消息先留待核对，防止只留下前半句。多事件可以生成不同候选；相同属性的矛盾输入无法分别提交成有效记忆。

这是保守的词面规则，无法证明任意自然语言的真实含义。无命中的文本不代表没有值得记忆的信息；复杂同义表达、隐含语境和指代仍可能漏记。单纯原文匹配或模型声明不能补上这层能力。

模型接口仅准备提示与接收JSON数据，没有执行器或供应商连接。模型只能提出category/assertion/value/details/start/end，不能提交账号、授权、事件ID、用户确认或最终存储动作。非法/额外字段、重复JSON键、重复条目、错跨度、伪造药名/单位、超长及截断回复均拒绝。模型意义只有与本地已验证的有限断言完全一致时才转成候选；其他有原话但未验证的意义返回待核对。因此目前没有通过模型扩展自由语言支持。

必要相邻语境接口最多两条、正文合计2048字节，要求同账号、同会话、较早消息与时间；相邻助手话语不能捐献成当前用户自述。“是的”仍不能自动变成疾病事实。提示正文省略账号、会话和数据库ID，只有当前消息及必要角色/语境；该提示在本轮未发给外部服务。

`personal_memory_intake.py`提供内部preview_new_message/save_new_preview，尚未注册页面或HTTP路由。适配器核对登录账号、指定会话的最后一条用户消息、重置游标、来源排除、会话版本和逐类许可，读取预览不建表或创建许可。最后一条消息检查本身不能证明全局“刚刚发送”；未来正式调用方还必须把实际新消息事件交进来，历史处理由P07的独立授权入口承担。

提交只接受消息ID及预览/原文/许可/会话版本，不接受客户端或模型构造的候选正文；从当前数据库重建候选再比较。已有同属性记忆先要求P04，不擅自匹配事件或覆盖旧状态。不同候选使用同一外层事务，后面的索引登记失败时前面的保存也回滚。P02继续负责来源复核、条件版本、回执和索引任务原子提交；重放不新增行。没有候选和失败均不会生成“已记住”的业务结果。

逐类收集关闭时不产生有效候选，旧auto_enabled不授予新健康权限；使用开关与收集许可继续分开。自动保存后的user_confirmed始终为false。原显式命令的现有页面确认流程保持，本轮新内部适配器不接管它。

## 开源评估和后续顺序

参考[LangMem结构化提取与自主控制保存](https://github.com/langchain-ai/langmem/blob/main/docs/docs/guides/extract_semantic_memories.md)的职责划分，其[MIT许可](https://github.com/langchain-ai/langmem/blob/main/LICENSE)允许复用；[Mem0](https://github.com/mem0ai/mem0)及其[Apache 2.0许可](https://github.com/mem0ai/mem0/blob/main/LICENSE)也可评估。两者通用提取都不能直接替代本项目逐字来源、主体、许可和版本保护；本轮复用模式，保留现有Python/Django合同，没有复制源码或安装新依赖。发行页面/API未提供可据以确认近期维护频率的完整信息，未据此指定新依赖版本或作成熟度背书。

下一步先准备P03单独的有限虚构聊天模型批次，明确模型、实际输入、调用次数、费用上限和停止条件后再执行；旧付费批次不重开。当前选择额外模型调用0次，不外发真实个人内容。真实同义表达、否定和指代指标必须使用实际返回评分，并把模型原始提议与经保护后可保存的结果分开统计；未知意义不能因为测试期待就自动放行。

随后才接P04的多来源目标、冲突、更正/补充、遗忘及旧上下文失效。正式0006迁移、回答接线和页面仍分别安排在后续阶段；迁移前另做当时数据库备份，已删除的Docker备份不能使用。
