## 原话如何定位

新协议`personal-source-quote-v1`的返回仅含contract/items，每项只含category/assertion/value/details/source_text。它不接受模型提供的start/end、账号、事件ID或确认状态。调用时明确选择`model_messages(request, source_quotes=True)`生成提示v3，并由`extract_quote_preview`校验；旧数值坐标协议仍保留，不根据输入内容猜测协议。

服务端在当前用户消息中逐字寻找source_text，找到唯一位置才计算Python Unicode码点下标。不会做模糊匹配、空格清理、标点替换、数字单位转换或自动补齐。引文不存在时拒绝生成候选；相同引文出现多次时要求澄清，不取第一个或由模型猜一个序号。相邻消息、助手话语和其他账号不能提供当前断言的原话。

**定位成功仍不代表含义通过。** 引文还须与本地已验证的完整本人断言一致，保留主体、时间、否定、不确定及明细。“我没有高血压”中的“高血压”即使唯一存在，也不能补成肯定自述；“昨天发烧”不能扩成“我昨天发烧了”。家属、假设、引用与未知同义表达继续拦截或待核对。该修复没有扩大疾病词表或直接信任模型意义。

完整原句只多一个末尾中文句号时，现在允许与本地证明等价。仅放行这一处终止标点，问号、感叹号、空格、数字小数点及限定词差异都不等价。候选仍保存可核验的完整断言，原文哈希保持整条消息；新协议另保留接收到的引文及实际定位跨度，区分原引用和规范候选。句号有无两个变体也不能制造两个相同有效候选。

旧协议越界坐标仍拒绝，不从旧返回的value或预期答案制造原句来补救。后续真实测试必须新建引用协议批次，不能把本轮合成引用当成模型已经正确引用。

## 临时要求如何判断

表达偏好单独经过长期/临时/混合/不明确四种范围判断，不把模型声称的偏好类别当作长期保存许可：

| 用户表达 | 当前处理 |
| --- | --- |
| 以后请尽量通俗一点 | 明确长期且符合已有有限偏好句式，可以产生候选 |
| 这次回答简短一点、本轮请简短回答 | 临时，不写长期记忆 |
| 先简短回答、暂时简短回答、当前问题简短回答 | 临时，不更新长期默认 |
| 请简短回答 | 长期范围不明确，不自行推断成长期偏好 |
| 以后请简短回答。仅在本会话有效 | 范围混合，先澄清，不选择其中一段覆盖默认 |
| 我今天测得血压135/85毫米汞柱 | 健康事件保留原时间；不会因为“今天”被错当成临时回答偏好 |

判断采用有限中文标志词，未覆盖任意口语表达。只有范围通过且偏好含义符合已有有限句式，才可能形成长期候选；“以后”等词不能绕过主体、引用、合法值与来源核验。对混合范围采取保守澄清，尚未实现任意复杂语境中分离两条独立要求。原聊天中临时要求的实际回答作用继续由既有模块处理，本步不修改回答流程。

两套模型协议都经过这道范围核验；本地提取也不再接受附带临时限定的长期句式。隔离ORM检查证明，已经保存“以后通俗解释”后输入“这次简短一点”，不会覆盖或新增长期条目。新提示v3明确规定没有长期范围、临时或混合要求不提议为长期偏好，并给出独立虚构负例；模型是否会遵守仍待真实批次验证。
