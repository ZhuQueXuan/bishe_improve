本轮新增16项必要检查，最终300项相关隔离回归通过。上一批原始真实返回的离线回放中，P03-03“医生说我可能有高血压”由有据本地规则补上，候选10→11，11项隔离保存/回读/唯一重放通过。0新模型调用，原模型漏记与评分仍保留。正式聊天、数据库与服务保持；新提示v3.2尚无新的真实模型结果。

## 现在记录的含义

| 用户表达 | 有据候选 |
| --- | --- |
| 我可能有高血压 | 本人疾病怀疑，suspected/uncertain |
| 我最近可能有高血压 | 不确定性及“最近”原时间词一同保留 |
| 我好像有高血压、我疑似有高血压 | 不确定自述，不能标成reported/current |
| 我怀疑自己有高血压、我觉得自己可能有高血压 | 记录本人怀疑的表达，不推断诊断 |
| 医生说我可能有高血压、医生怀疑我有高血压 | 记录用户转述的对本人怀疑，不能标成医学确认 |
| 我去年可能有哮喘 | 状态仍uncertain，原时间“去年”保留，不归一化成现在确诊 |

扩展只覆盖原五个疾病标签高血压、糖尿病、哮喘、冠心病、慢性肾病及明确有限句式，没有增加自由疾病推断或其他数据类别。没有主语的“可能有高血压”、主体不明的医生怀疑、家属、假设、问题、引用、可能没有/不确定有没有等复杂否定，仍保守澄清或不提取。不能为了记住“不确定”就默认每条怀疑都指用户本人。

每项保留完整断言，不剥离“可能”“怀疑”“疑似”；断言suspected与状态uncertain在P01合同中绑定，P02保存与读取仍按来源核验。用户确认与医学确认继续分开，自动候选不变成已确认记录。新信息与旧同属性状态如何更正、关联事件仍交P04；不会用这轮补漏静默覆盖原有断言。

## 模型漏提取时如何补记

新引用协议的完整合法响应可能返回空items，例如上一批P03-03。现在只对当前消息中由有限本地规则明确核实的“不确定本人疾病自述”补漏，不把模型的空结果理解成“用户没说过”。补漏必须同时满足：

- 当前来源角色/账号/会话合同有效，类型收集许可明确开启，完整原话和整消息哈希有效。
- 引用协议响应完整且合法，所有模型所给引用均已消歧；格式失败、半截JSON、缺失/重复引文时不补救成成功。
- 本地明确得到self_disease_report/suspected/uncertain，原句唯一，带完整主体、时间与不确定限定。
- 模型没有对同一实体提出另一条需要审核的提议，本地也没有同疾病不同断言或不同时间的待关联事件；这些情况留待核对。
- 该候选尚未存在于已通过集合中，合计不超过原5项上限。

模型已经正确提出同一条不确定自述时不重复增加；如果模型把“可能”升级成肯定、截掉限定、改成另一类别或引用不完整，不自动把该错误修成成功提议。一般肯定/否定疾病、用药、偏好及任意未知信息均不在本轮补漏范围。旧数值坐标协议没有增加通用兜底；当前无模型的本地预览也能按新增有限句式产生不确定候选。

模型原始返回和source_text定位列表不变。预览新增local_uncertain_completion，记录补漏策略版本与新增候选ID，并用candidate_origins区分model_quote和local_uncertain_rule；补出来的是本地规则来源，绝不制造模型引文。预览指纹包括合并后的候选及补漏信息，原source_hash仍覆盖整条消息。

P02继续保存自动候选及其原话，自动来源不等于确认状态；规则/模型的细分信息目前在预览与本轮审计报告中保留，没有改P02数据结构或给旧聊天补填元数据。正式接线时还需决定如何携带该审计信息，不能声称已有线上完整追踪页面。
