## 三 目标处理流程

```text
新用户消息持久化并建立唯一处理身份
  → 核对逐类收集及对应云端处理许可
  → 模型读取当前消息和必要语境，提出候选与证据
  → 程序校验格式、来源、账号、权限和版本
  → 语义复核主体、否定、时间、细节及更正关系
  → 自动保存 / 待确认 / 不保存 / 处理失败
  → 事务提交新版本与任务回执，传播失效

后续问题
  → 判断一般知识、个人适用性或历史回顾
  → 结构读取相关背景，回源复核有效资格
  → 个人背景与专业证据分别进入回答
  → 展示可核对来源，支持更正和遗忘
```

“没有值得记的内容”“未理解清楚”“服务失败”必须分别记录，不能统一当作成功空结果。未保存时不能回复“已记住”。消息接收成功与提取、回答成功也分开记录，重试使用同一操作身份，不重复创造消息或记忆。

### 提取和语义复核

提取候选拟包含主体、类别、原始名称、肯定或否定方向、确定程度、原时间词、事件状态、与旧信息的关系、支持来源及待核对原因。具体字段和枚举在R1固定。模型可引用服务器提供的局部消息标识，账号、数据库键、事件身份、目标版本和最终动作仍由服务器绑定。

对当前消息保留完整文本，对相邻语境使用有界窗口。语境截断若可能丢掉主体、否定或更正，结果必须带“不完整”状态并转核对，不能当成完整语义支持。来源引用可以跨必要的多条用户消息；助手文字可提供对话语境，不能单独充当用户疾病事实。只有“是的”而缺少可验证的用户依据或明确确认目标时，不自动构造病史。

硬校验负责可确定检查：消息所有权、角色、收集和处理许可、合法结构、数值单位原样、原文存在与消歧、哈希、排除来源、版本及预算。它不再用整句正则判断模型含义是否成立。名称归一化如有需要，应单独保存原词和有依据的映射；不得通过知识补全药名、剂量或医学诊断。

语义复核读取候选、支持原文以及可能推翻它的相关语境，输出“有支持、被反驳、无法判断”，并给出对应来源和缺口。复核不能只重读选中的前半句。初版对新健康候选、主体变更、否定与更正安排有界复核；普通偏好不默认每次双调用。第二次模型判断仍可能错误，不能把两次同意或模型自报置信度当作正确证明；复核的实际成本与净收益单列评估，必要时采用用户确认路径。

“我可能有高血压”是含义明确的不确定自述，可以保持suspected/uncertain。“我可能没有高血压”必须保留否定方向和不确定程度；旧合同不能表达时先待核对，不转换为“可能患有”。不能用新含义字段重写旧返回或旧评分。

### 保存和确认策略

候选状态、保存资格与用户确认是独立维度。待确认候选不作为跨会话有效事实使用；开放自动收集后，有充分支持且符合类别策略的自动条目可以未逐条确认，但始终标明自动来源、自述和原确定程度。

| 情况 | 目标行为 |
| --- | --- |
| 明确长期偏好且许可开启 | 自动保存，提供查看和撤销；临时要求继续只作用于原范围 |
| 明确本人疾病自述或本人怀疑 | 初期以候选确认验证流程；该类别通过开放门槛后可自动保存，不因出现“可能”反复询问 |
| 主体、对象或事件关系不明 | 只询问当前缺口；没有足够依据不猜测，不要求用户套固定句式 |
| 关键冲突、错误归属及重要更正 | 先停止使用受影响的旧确定状态，核对关系后提交；更正不能通过“最新入库优先”决定 |
| 假设、引用、普通问题或家属信息 | 不保存为本人事实；家属未开放时只纠正错误本人归属 |
| 非法回复、超时、权限关闭或版本过期 | 不自动保存，保留可理解的失败状态及有界重试方式 |

确认绑定具体候选、证据哈希、许可和目标版本；用户通过聊天回答或点击确认时重新核验。原话、许可或旧目标变化后，旧确认不能提交。一次简短问题应能完成核对，例如“刚才说的是你父亲，要撤回本人高血压这条记录吗”，无需结构化表单。确认保存不代表确认患病，更不等于医学核实。

初期健康候选确认是分阶段启用措施，不是永久逐条确认要求。自动模式按类别分别开放；未达到语义和闭环门槛的类别继续候选确认或关闭。不能用“所有内容都转人工确认”冒充自动理解效果通过。

### 跨会话使用与信息更新

一般知识问题默认不附带个人病史；个人适用性问题读取相关类型的有效背景，即使用户没有重复疾病名；历史回顾按事件、时间和来源说明当时自述。主体为家属时不能借用本人记录。没有命中不等于没有病史，未知时间不等于当前状态。

候选选择先依靠结构和关键词，不以个人向量就绪为前提。相关背景过多时缩小范围或核对，不悄悄截去关键项。进入模型上下文前及返回回答前复核所有权、使用许可、来源、当前版本、争议和遗忘状态。个人背景保留原限定，不作为专业医学依据；本项目资料范围不能支持的诊疗或药品适用性结论仍须说明不足。

更正关系分为补充、同事件变化、不同事件、明确撤销或纠正、未解冲突。模型提出关系及候选目标，服务器只提供当前账号有资格访问的目标并检查版本。不同年份同名事件不默认合并；“最近血压正常”不自动删除既往疾病自述；“我说的是我父亲”应撤销错误本人归属，家属未开放时不另建家属档案。未解关键冲突应保存待核对状态，不能仅返回一个澄清文本而继续使用旧确定事实。

### 遗忘与全链路失效

遗忘先使读取资格失效，再清理派生物。业务事务提交遗忘状态、版本变化、正文清理、相关来源排除及删除任务意图；所有关联重复来源也参与排除。后台任务持有旧许可或旧版本时不得提交，即使模型已返回也要拒绝。保留防重放所需的最小标识，不在失效标记中复制被遗忘正文。

摘要、对话缓存、暂停任务、前端续做入口和在途输出均绑定相同的有效版本。未来即使向量删除尚未完成，回业务库核验也必须立即拒绝旧内容。原聊天保留与删除聊天是不同操作：保留旧话时，仍不得从排除来源重建被遗忘记忆；后续新的明确保存请求按新来源、新版本处理。不得承诺撤回已发送给云端的请求。

### R1 调整候选合同与程序硬校验

对应原P01、P02的兼容扩展。固定主体、肯定/否定、确定程度、时间、关系、证据集合、提取/复核来源、确认和资格字段。新旧合同明确区分，采用新适配器，不把额外字段直接塞入旧validate_record。对多证据保存设计逐条消息哈希和语境版本；旧单来源记录维持原解释。

**验收标准：** 非法字段、伪造主体权限、跨账号/助手证据、无来源、重复歧义、缺失否定/单位及过期来源全部按预期拒绝；相同含义的合法同义表达不因本地句式不匹配而被硬校验拒绝。未知病名可保留原词，不能创造标准病名映射。旧合同和旧确认语义不变；本步使用合成输入，只验证结构与保护。

### R2 实现语境提取与语义复核接口

对应原P03。替换固定句式作为意义必经门槛，建立模型候选、硬校验、语义复核和明确失败结果的纯接口。保留有界输入、格式限制和来源定位；规则补漏是否保留由对照决定，不承担兜住全部自然语言的责任。

**离线验收标准：** 替身覆盖跨句主体修正、不确定否定、混合偏好、相邻语境缺失、提示注入、截断和复核分歧；每个结果可追踪到原文，错误回复不产生有效候选。隔离接口现按63完成，正式业务调用仍待后续接入；替身成绩不等于真实语义通过。

**真实语言门槛：** 另获有限虚构批次授权后，冻结当前源码、参数、输入、评分及费用停止条件再执行。逐例分别报告原始提议、复核判定、最终候选、漏记和确认次数。核心范围内明确应记正例应得到正确候选，歧义样例得到可完成核对，不应记项不得成为有效本人记忆；未达预声明标准的类别不开放自动模式。来源完整不单独算语义正确，两次模型同意不单独算正确。一次失败保留结果，不按结果连续付费追成功。

### R3 接通确认和更新关系

对应原P04和P09的决策部分。在隔离环境建立待确认、被反驳、争议、已提交和撤销等可区分状态；确认绑定候选及版本；补充、同事件变化、新事件、更正和遗忘使用不同动作。用户更正优先于未完成提取。

**验收标准：** 一次有针对性的回答或点击可以完成确认；证据、许可、目标变化后旧确认拒绝。跨句或下一轮“说的是我父亲”不能继续产生有效本人事实；关键冲突在解决前不能作确定背景；疾病存在与近期测量正常不被错误互相覆盖。临时要求不改长期默认，用户确认不升级为医学核实。这里只做隔离确认与决策，不开放正式账号收集。

### R4 接通新消息处理和版本化持久化

对应原P02及P03接线。明确先保存用户消息、再安排提取和回答的时序，分别记录接收、提取、确认、保存及回答状态。使用稳定消息身份和请求键，新增有界任务或同步适配由实现时选择，不默认引入常驻调度框架。消息保存后即使回答失败也可核对处理状态；重试不能重复写入。

**验收标准：** 合成磁盘库中完成真实消息持久化、预览、保存、关闭连接和新进程回读；原话、限定、主体、时间和确认标记保持。多候选故障整体回滚、同键重放不重复、两个窗口只允许合法当前版本提交；失败有界且不冒称已记住。使用新受信入口提交，不能仅用测试脚本直接调store替代聊天接线成绩。

### R5 接通跨会话结构检索与回答

对应原P05及P08。为一般知识、个人适用性、历史回顾建立读取策略；从新记忆表选择合资格背景，补全当前旧选择器无具体病名时的缺口。模型输入分列个人自述和专业证据，保存实际选入/排除理由。个人向量仍不接入。

**验收标准：** 在隔离真实HTTP中，从第一次聊天保存到第二次未重提病名的相关问题，确实送入正确背景；一般知识不无关带入、家属问题不套本人、待确认/争议/失效项不作确定事实。检查实际最终模型输入，不能只看检索列表。替身接线与真实模型是否保留限定分别记录；真实遵循需单独授权批次，不由HTTP通过推定。个人背景缺失不被描述成没有疾病或药品安全。

## 五 核心多轮验收场景

以下是场景要求，不是已运行成绩。R0已按61建立具体虚构输入、预期来源或目标关系和各阶段预期；功能结果均未执行。后续按冻结身份验收，不改写预期迎合实现。

| 普通同义表达与陌生病名 | 不要求固定句式；有本人依据时形成原词候选，未知映射不猜测 |
| 本人可能患病 | 提取、确认或自动保存、跨进程回读及回答均保留不确定，不升级确诊 |
