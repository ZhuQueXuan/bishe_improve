# R0首版范围与独立验收基线

2026年10月28日。按[60号方案](60_规划_自然语言记忆提取与跨会话闭环调整.md)完成R0的范围、虚构样例、实现前验收口径和保护基线。当前没有实现R1及后续功能，也没有获得新的语言模型或端到端成绩。

用户本次授权止于R0准备：不做付费测试，不扫描真实聊天，不迁移正式库，不重启服务。本轮未导入Django或调用业务提取器；只用Python标准库生成、校验离线评测资产，并以只读连接查询正式库迁移和表名元数据。正式应用版本文件仍为1.0.2，正式迁移止于0005，新个人记忆表不存在；没有探测或重载正在运行的服务。

## 一 首版范围已经固定

| 项目 | 本轮固定的目标范围 |
| --- | --- |
| 本人疾病自述 | 支持本人明确疾病表达、疾病怀疑、否定及不确定方向；名称保留原词，不限原五个标签，不要求特定句式 |
| 表达偏好 | 回答风格plain/technical与篇幅brief/detailed；日常同义说法可理解，值与作用范围保持有限 |
| 首个开放模式 | 健康信息先候选确认，清楚的长期偏好按许可自动保存；此处只是未来策略，不改变任何真实开关 |
| 后续自动健康模式 | 仅在相关语义、权限、更新、遗忘及使用闭环通过后按类别开放；明确支持的本人肯定/怀疑自述可成为自动候选，不因“可能”反复确认 |
| 否定及方向不明 | 保留原方向和确定程度，首版走确认；不得据此静默清除既有病史，也不得转换成肯定疑似 |
| 时间 | 区分原话时间与发送/入库时间；保留过去、当前自述或未说明，不推断今天仍患病、康复或医学确认 |
| 账号与来源 | 已登录账号的新用户消息及必要有界相邻语境；原文、账号、哈希和版本由服务器核验 |
| 云端与历史 | 收集、使用、云端提取、云端复核、云端回答个人上下文分别选择；历史搜索、历史补提取和个人Embedding均关闭且后置 |

这里“疾病自述”记录的是用户表达过什么，并不核实疾病是否真实。用户说自己被确诊，也只形成其确诊转述；用户确认保存同样不等于医学确认。否定方向和确定程度是本轮预期含义的标注，R1还需设计新版本合同，不能直接写入旧P01合同。

同一消息可以包含两种疾病，或同时包含长期风格与本轮篇幅要求；不能因出现临时词就整条拒绝。相同偏好字段范围互相冲突时，只核对冲突的范围。陌生病名保留原词，不因知识图谱无该词而拒绝，也不猜测别名或医学诊断。

以下新收集暂不开放：用药、过敏/不耐受、症状、测量、检查、阶段健康状态、新学习背景及家属档案。旧版已存在的手动或有限学习背景行为保留；其他P03隔离类型成果不删除、不作废，但不因已写过提取规则就列入首版上线范围。专业RAG、原134专业向量及原显式确认保存机制保持。

## 二 样例与保留集已经分开

资产目录为`bishe/data/natural_memory_v1/`，专门用于非运行时的范围与评测材料，不是新模型、数据库或已经上线的“记忆v2”。

| 材料 | 数量 | 使用边界 |
| --- | --- | --- |
| 开发单条表达 | 18条，含12项预期事实 | 可供R1以后理解需求、设计接口和调试；另有3条应澄清、4条不保存，11条产生提议，其中1条含两项事实 |
| 保留单条表达 | 12条，含9项预期事实 | 不进入提示示例或规则调参；冻结源码与提示后才用于验收 |
| 开发多轮脚本 | 6条 | 跨会话使用、不确定保存、主体修正、偏好范围、事件与版本、遗忘重放 |
| 保留多轮脚本 | 6条 | 账号与云端许可、关键冲突、未开放类型、技术失败、过期确认/撤销、回答与旧续做失效 |
| 总计 | 30条表达、12条多轮脚本，共42个唯一身份 | 全部为虚构输入；所有功能结果均为null，均未执行 |

单条样例将预期事实与支持它的用户原话关联，保存消息标识、跨度和哈希。多轮脚本固定操作顺序、虚构用户输入、目标关系及应观察状态；其中预置记录必须在未来隔离执行时创建对应的虚构来源消息，不能以裸候选绕过来源核验。脚本中的账号A/B和许可均为测试设定，不映射或开启真实账号。

开发材料覆盖普通同义疾病表达、原五标签之外的名称、医生怀疑、过去自述、明确否定、不确定否定、单消息多事实、自然表达偏好、长期与临时要求分离，以及家属、假设、引用、测量不能推断疾病、主体不明和仅助手给出病名的指代。

原P00、原16条真实开发输入及59的12条针对性输入保持原样，继续作为已见历史证据，不进入本轮保留成绩。当前程序与300项旧回归没有在这些新材料上运行，因此不能报告新覆盖率或把预期事实数写成模型正确数。

### 独立性的具体含义

本轮独立验收口径的含义是：先于新实现固定预期，不从实现返回反推标签；开发与保留材料分开，判定不依赖某个具体运行时JSON格式，也不要求生成答案逐字一致。

两集合由本轮同一协作者编制，作者已知晓内容；它们不是独立作者盲测，也没有医学专业复核。精确用户文本无交集，不代表语义模板完全未见或统计独立。场景类别本就来自60的公开要求，不据此宣称泛化结论。

R1至R7的开发任务不要打开`acceptance/r0_reserved_cases.json`，也不要读取含该集合全文的一次性生成脚本`temp/build_natural_memory_r0_20261028.py`。验收时先冻结代码、提示和计划，再由验收入口读取。若保留内容被用来修提示、补规则或作为开发示例，应记录暴露，原文件和首次结果保留，另建前瞻保留材料；不能继续称为未参与调参。R0结构检查读取这些材料不等于已有独立语义验收。

## 三 验收口径与开放条件

完整机器可读口径在`r0_acceptance_contract.json`，与范围和样例一起冻结。以下指标同时报告分子、分母和逐例结果；空分母写null，不能写100%。

| 层次 | 评价内容 | 通过条件 |
| --- | --- | --- |
| 原始提取 | 类别、主体、实体原词或偏好、否定方向、确定程度、原时间及完整用户证据 | 核心应记事实正确产生；重复提议最多算一项正确，额外无依据内容算误提议；程序拦截不能抹掉原始错误 |
| 程序与语义复核后 | 有效候选精确率/召回、正确澄清、无必要澄清、来源支持 | 核心预期含义逐例符合；应澄清项问到具体缺口；清楚正例不能靠无声漏记或一律提问蒙混通过 |
| 保存与确认 | 初始确认模式、未来可自动模式、确认过期与失败回执 | 待确认健康候选不作为有效背景；保存前重验许可和版本；用户确认与医学确认分开 |
| 多轮使用 | 合资格记忆集合、语境限定、原话、事件与版本、最终实际模型输入 | 12条脚本按开发/保留分别逐项通过；跨会话相关问题不依赖重提病名，一般知识和家属问题不错误带入 |
| 回答 | 个人主张、来源与专业依据关系 | 人工核对实际回答，保留否定/不确定/时间；不能只凭E编号合法或检索列表正确判通过 |
| 核心保护 | 账号、外发许可、来源、不确定升级、遗忘复活、过期覆盖 | 固定关键场景0违规；任一违规则相关类别不开自动模式 |
| 自动模式 | 已预标注可自动的清楚事实直接正确保存的比例 | 在明确开启自动模式的验收口径中逐项通过；健康确认初期不计作直接自动成功，一律确认不能通过自动开放门槛 |

提取正确一项，需要预期关键语义及必要来源同时成立。过去的诊断转述不推定今天仍患病；“可能没有”不推定“可能有”；否认助手曾下的结论不自动等同于用户否认疾病。普通字面匹配和第二次模型同意都不能单独证明含义成立。

技术失败另行计数。非法JSON、截断、超时、用量未知和缺失样本不能算成正确空结果；正例对应事实计入漏记或未完成。模型提议、程序或规则补记、用户确认、实际保存与最终回答分别留证，不能合并为一个“通过率”。

第一次保留验收失败后记录首次结果，失败类别保持候选确认或关闭。不得为追求通过擅自增加费用、删除失败题、改预期、扩大上限或选优重跑。有限集通过只支持其声明范围，不是通用自然语言质量或医学可用性证明。

## 四 有界输入与未来测试上限

以下是为后续实现固定的上限，不是当前运行配置，也不是本轮付费计划。真实调用仍需按确切载荷重新核算预算并获得相应授权，不能使用旧批次余额。

| 项目 | 固定上限或规则 |
| --- | --- |
| 当前用户正文 | 4096 UTF8字节 |
| 必要相邻语境 | 最多4条、正文合计4096 UTF8字节；需要的主体/更正被省略时显式报告缺口 |
| 完整模型请求 | 包含提示、结构及包装后的messages最多32768 UTF8字节；不能只算用户正文 |
| 候选与回复 | 最多5项；回复JSON最多8192 UTF8字节；单调用最大输出1024 tokens |
| 提取与复核 | 每条新消息最多1次提取、1次语义复核；偏好不默认复核两遍 |
| 超时与重试 | 单调用最多45秒且不超过原剩余时间；SDK自动重试0；原前台90秒截止不重新开始 |
| 超限 | 明确预算不足或语境缺口，不裁掉限定后继续猜测，不伪装成功 |
| 本轮外部授权 | 模型、复核、Embedding请求0；付费预算0元；不生成可自动启动的付费运行器 |

原P03为当前消息4096字节、相邻2条/2048字节；上表扩展是未来设计，当前业务源码和限制没有修改。R1/R2应核对这些边界与实际提示大小是否匹配；若不能在固定上限内工作，应保留失败并先修提示或缩小处理范围，不能暗自提高上限。时延、用量和成本将来按真实尝试记录，本轮文件检查耗时不作为线上性能成绩。
