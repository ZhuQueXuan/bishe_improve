# R1新版候选合同与来源硬校验

2026年10月28日，承接[60调整方案](60_规划_自然语言记忆提取与跨会话闭环调整.md)和[61 R0基线](61_过程_R0首版范围与独立验收基线.md)，完成R1的独立候选合同、受信来源快照、原文定位和程序硬校验。新增32项检查，最终332项相关隔离回归通过，含原300项。

本阶段仅实现隔离纯函数，没有改变正式提取、聊天、页面、模型、迁移或保存接口。新版合同可以表示不限五病名的原词、普通同义表达，以及分开的否定方向与确定程度；当前正式系统仍走旧逻辑。所有新版结构校验结果均不可直接写入，语义提取和复核继续R2。

## 一 新旧合同分别保留

新增`api/natural_memory_contract.py`和对应测试文件，不修改原`memory_contract.py`、`personal_memory_contract.py`、P02存储、P03提取、模型或0006迁移。新合同没有适配成旧candidate，也没有把新含义强行映射回旧assertion枚举。

| 新合同标识 | 用途 |
| --- | --- |
| natural-memory-source-v1 | 服务器捕获的完整有界消息与来源、许可版本和会话版本 |
| natural-memory-candidate-v1 | 仅表达模型或受信本地逻辑提出的含义及引文 |
| natural-memory-proposals-v1 | 结构化回复的根对象，含contract和items |
| natural-memory-grounded-v1 | 结构与来源通过后的本地候选包，仍须语义核验 |

新候选只有contract、category、subject、content、time、relation、evidence七个字段。疾病content保存value_raw、polarity、certainty；偏好content保存slot、value、scope。疾病名称必须逐字存在于用户证据，但不限五个标签，也不调用本地整句解析器证明含义。名称归一化、标准名、诊断推断和新增药物/剂量字段均不接受。

polarity为affirmed/negated/unknown，certainty为asserted/possible/unknown。因而“可能有”和“可能没有”可以保持不同方向，不会因为旧合同只有suspected/denied就静默改义。时间只接受原话及past/current_report/unspecified范围，不接受模型补出的标准日期；无原时间依据时不允许声明过去或当前时间范围。偏好仍限风格和篇幅，不扩为新的背景收集。

relation仅是new_information、supplement、same_event_update、new_event、correction、new_default、retraction或unresolved等建议。它不能指定数据库目标键或授权更新；事件关系与目标验证留R2/R3/R4。未知、家属和其他主体不作为本人候选通过，后续应由R2的澄清或不保存结果表示。

## 二 模型引用局部标识 服务器绑定真实来源

候选证据只含source_ref和text。source_ref使用current或context_1至context_4；不要求模型返回数据库消息ID、原文哈希或字符坐标。服务器从已核验的来源顺序映射真实消息，定位唯一原文，再补入Unicode跨度、整消息哈希和原发送时间。

例如以下仅说明开发材料中的合同形式，不是实际模型返回：

```json
{
  "contract": "natural-memory-candidate-v1",
  "category": "self_disease_report",
  "subject": "self",
  "content": {"value_raw": "银屑病", "polarity": "affirmed", "certainty": "asserted"},
  "time": {"raw": null, "temporal_scope": "unspecified"},
  "relation": "new_information",
  "evidence": [{"source_ref": "current", "text": "我患有银屑病。"}]
}
```

`capture_context`要求调用方显式提供账号、会话、许可版本、会话版本、逐类收集选择、重置游标和来源排除；不会从旧auto_enabled推断新许可。它校验来源归属、角色、消息顺序和带时区时间；当前必须是用户消息，相邻助手文字可留作语境，但不能成为用户事实证据。必须至少引用一处当前用户证据，防止把单纯旧话当新消息结果。

快照绑定全部有界消息正文、哈希、排除集合、游标和版本。验证候选时重建快照，并与受信调用方捕获的预期digest、许可版本和会话版本比较。即使选中的引文没变，外围语境变化也会拒绝。重复原文无法唯一定位时拒绝，不取第一处，不补原句，不修坐标；缺失、助手或不属于该来源快照的引文不能使用。

快照哈希不是登录认证或数据库锁。当前函数只能约束受信调用方交入的快照；真正持久化消息所有权、最新政策、重置和排除状态仍须R4在数据库重新核验。不能让前端自报快照、版本或账号后直接调用保存。

## 三 结构通过仍然不可写入

每个通过的候选包都带有：

- validation_level为structural_only，requires_semantic_validation为true。
- writable、writes_performed、user_confirmed和clinical_confirmation均为false。
- 模型/本地规则origin分开标记，不能由候选字段伪造。
- 完整有界semantic_context以及真实来源groundings，避免R2只看到模型圈选的前半句。

这是一份本地包，包含账号和来源元数据，不能整体作为供应商载荷。R2必须另行构造经过许可的角色、正文和局部标识输入，去掉账号、数据库键和服务器哈希，并再次检查完整messages预算。

程序能够确定地拒绝：非法/额外字段、假类别、未许可类别、类型错、伪造确认状态、无来源、改写引文、歧义引文、助手证据、错误实体原词、虚造时间原词、陈旧版本、缺失上下文和越界预算。当前首版不接药物/测量类别，dose、unit等额外字段及类别直接拒绝，未宣称已完成其未来语义验证。

程序不能仅靠字符串定位证明主体、否定、确定程度、长期意图和事件关系真实成立。例如给“我没有银屑病”附一个错误的affirmed字段，物理引文可以存在，结构也可能合法；测试明确要求它仍不可写入，且完整原话必须留给R2。R1完成的是结构与来源边界，不能据此声称已自动拦截一切截掉否定或误归主体的提议，也不能恢复逐句正则来冒充语义复核。

空items仅代表合法结构，不等于“不应记内容”的正确负例。多候选回复中任一项不合法则整批拒绝，不部分返回成功。重复JSON键、NaN/Infinity、截断及超过8192字节的回复均拒绝；有效重复提议不能重复计数。

## 四 边界与兼容性

R0冻结上限保持：当前正文4096 UTF8字节，相邻最多4条且合计4096字节，回复8192字节，最多5候选。新增完整messages检查包含提示及JSON包装，最多32768字节；这只是未来R2派发边界的本地检查，没有创建模型请求。输出token上限、45秒单调用与原90秒期限仍是R0的未来执行要求，本阶段没有供应商执行器，也不声称已经在网络调用中强制执行。

新候选与grounded包均被旧P01候选校验器拒绝，不能误混入原store。当前没有新旧记录转换器，旧自动来源、已确认HealthMemory及suspected/uncertain的原含义保持。新确认状态、争议状态及多来源入库由后续阶段处理，不在本步增加表或调整正式0006。
