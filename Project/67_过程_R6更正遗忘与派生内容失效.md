## 二 统一失效凭据

每份派生内容绑定所属账号、问题会话和精确来源标识、聚合revision、账号epoch、状态摘要、政策、提取/复核许可、回答许可、原消息信封摘要、会话重置版本及最新用户消息。另有正文摘要和绑定摘要，检测字段漂移。摘要不能认证用户身份；读取和继续仍须实际账号鉴权。

新消息、提取/复核产生的决策、确认、更正、重复来源关联、暂停/撤回/遗忘、各项许可变化及会话重置，均触发同事务失效。派生正文置空，状态转为stale；旧回答票据停止继续，清除续做/交付句柄，保留原期限和已经用掉的调用次数。账号范围采用保守失效，某项变化也可能使其他旧派生内容需要重建，不静默复用它们。

来源被直接编辑、排除或重置，即使调用方没有推进聚合版本，读取时仍精确回查已有绑定。发现不一致则不给正文并清空该副本。回查只涉及已绑定标识，不遍历账号聊天文本。目标版本变化也包含在聚合状态摘要中。

cache保存准备好的实际输入，summary只保存带限定的结构化自述/偏好，checkpoint保存继续该阶段所需内容，answer_view保存可再次读取的当前回答。它们都是内部受信生成，不接受HTTP上传任意派生正文。上限为每账号128项、每份正文131072字节，超限拒绝；原R3—R5容量上限保留，长期保留策略仍需启用前处理。

## 三 遗忘、更正、重置和权限

遗忘先沿用R3清空目标全部提取版本、关联引文和确认内容，排除已链接的旧来源；同一事务清空缓存、摘要、暂停点、回答读取副本和待处理模型任务。两个不同消息都补充过同一事件时，两份关联来源一起排除。原ChatMessage保留，不能用这些保留聊天自动恢复被遗忘的记忆；新的明确用户来源仍可重新提议，且须新确认，旧排除标识保持。

更正后的版本保留新断言，旧检查点、旧确认、旧任务和旧派生输入不能覆盖它。本轮实际组合检查把已保存的银屑病怀疑更正为湿疹怀疑，再尝试旧继续，旧内容没有覆盖新版本。主体纠正仍依赖有据的语义回执和明确目标，本轮不新增自然语言意图识别器。

新增隔离reset接口推进会话memory_version和memory_after_id，清旧待确认计划、任务及派生内容，保留聊天。来源属于该会话的条目不再有当前使用资格；无关会话的存储内容不被批量改写。

| 操作 | 对新收集和既有使用的区别 |
| --- | --- |
| 关闭收集 | 停止新收集，既有记录是否使用仍由使用开关决定；旧派生内容失效 |
| 关闭使用 | 已保存背景不再进入回答；逐类收集选择不被改成关闭 |
| 撤销云端提取 | 不再安排该提取路径，旧提取任务和派生继续失效 |
| 撤销云端复核 | 不能绕过本人健康复核后保存；已有合资格记录的使用仍独立 |
| 撤销问题用途或个人回答外发许可 | 对应请求不再派发，旧个人回答/继续失效；不擅自抹掉用户已保存的记录 |
| 关闭收集和云端处理后遗忘 | 管理入口仍可执行，清理不以再次提取或模型同意为前提 |

未来个人向量接口仅预留相同账号、条目版本、epoch、政策及内容摘要的失效要求，未创建集合、Embedding或同步任务。

## 四 真实暂停、继续和回答读取

新增隔离路径`questions/pause/`在用途判断和最终输入准备完成后、回答调用前暂停。此时用途调用已用1次、回答0次，准备好的cache和summary与checkpoint共享同一凭据；没有虚构“回答已经完成”。

`resume/`先鉴权和检查凭据、原问题时间加90秒的截止、已用次数及票据状态，在事务内一次领取检查点并清空其持久化正文，再执行原回答阶段。恢复不重做用途判断，不刷新期限，不给新回答机会；单次调用上限仍为45秒和原剩余时间的较小值。

同一暂停点再次领取、两个窗口竞争、旧格式token、过期或更正/遗忘后的暂停点均不能重新执行。如果进程在领取提交后退出，本轮采取保守停止：新进程不能判断未见回执的副作用是否发生，因此不自动重试，也不把原预算重置。用户可另发新的明确问题，但这不是恢复旧任务。

回答返回后保留R5的精确最终输入复算，再把助手消息、审计及派生内容同事务提交。隔离视图发出正文前再次读取answer_view，`results/<key>/`以后读取也逐次检查；失效时只返回不可用状态，不返回旧正文。保留的历史助手消息和当前可用回答是两种读取用途，历史保留不表示可以作为当前有效背景。

响应带owner、会话、revision、epoch、政策版本和回答许可版本。新客户端守卫只接受与当前页面状态完全一致的响应，版本回退、换账号/会话、退出和旧响应均拒绝。它是客户端漂移检查，不是身份认证或已接页面的证明。R7必须在真实store/页面应用它，并核对发送途中变更及旧续做按钮。
