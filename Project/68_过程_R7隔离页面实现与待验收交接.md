## 已实现的范围

独立入口为 `bishe/knowledge-graph-frontend/src/natural-memory-main.js`，页面为 `src/views/NaturalMemoryPanel.vue`。正式 `main.js`、路由、ChatWorkspace、账号及聊天store均未接入新链路，旧显式保存和管理流程保留。隔离页面使用同源HTTP，不读取正式token存储，不在本地存储凭据、聊天或个人记忆。退出和换账号会清空当前页面状态。

| 用户操作 | 实际实现与限制 |
| --- | --- |
| 设置 | 本人疾病收集、偏好收集、使用已存记忆、云端提取、云端复核、当前问题用途判断、个人背景云端回答、自动偏好意愿分别保存；设置及回答许可在一个事务内完成，版本不匹配则拒绝。设置读操作不初始化账号、不继承他人开关 |
| 发言与确认 | 当前发言先落入合成库，再由服务器注入的离线工作器处理。页面不提交模型回复或候选JSON。待确认、无可记内容、未接工作器、处理失败分别展示；没有保存时不说“已记住” |
| 查看依据 | 显示原话与记录时间、原确定程度、原事件时间、确认或自动来源、暂停和争议状态；用户确认不改变医学核实状态 |
| 更正与关系 | 可以明确选择旧条目作为更正目标，或声明另一事件；服务器仅把单个已校验疾病候选绑定到该目标版本。更正先停用旧确定状态，再确认新表达。目标不明或多候选不猜测 |
| 跨会话回答 | 新会话通过R5结构读取；回答单独展示模型引用的个人自述和专业资料，保留名称、怀疑、事件时间与专业页码/版本。专业依据与个人自述分开保存于受R6保护的回答副本中 |
| 管理 | 暂停、恢复、撤销使用、核对后保留原记录、遗忘及会话上下文重置均复用R3—R6接口；遗忘有说明与二次点击，原聊天保留和排除旧来源的语义分开说明 |
| 续做与在途响应 | R6客户端守卫已接控制器。每次变更先收起旧回答/续做；返回后重新读当前版本，再决定是否展示回答。账号切换、会话切换、退出、失效通知和读失败会清除派生显示。暂停显示原期限，只能领取一次 |
| 网络异常 | 写入结果不明时保留相同请求键及原请求体，提供“重试同一次操作”；不自动改键重发。双击只发一个在途写操作。读失败收起个人内容 |
| 跨窗口与刷新 | 广播只发送变更信号，不传个人内容。重新聚焦/可见时核对；可见空闲页面每3秒核对版本。整个浏览器刷新后需重新连接虚构账号，不自动恢复旧续做。该策略是有界刷新，并非跨浏览器瞬时推送 |

R7没有接真实提取SDK。未知的离线样例明确返回处理失败，不能据此评判真实模型对普通聊天的理解能力。自动疾病保存仍关闭；自动偏好仍受可信服务器门槛控制，浏览器无法提交该门槛。

## 实际页面验收交接

**先由用户将当前对话切到 GPT-6.1 Terra，再开始 Computer Use。** 不创建新对话，不向其他任务发消息；本轮没有对正在运行的模型做任何设置变更。

验收前重新阅读当前可用的 computer-use SKILL.md 及其要求；优先使用可用浏览器工具。若浏览器或Computer Use被禁止，停止该部分并如实记录未验，不用隐藏浏览器或构建检查替代。固定脚本为 `temp/run_natural_memory_r7_panel_20261030.py`，仅供离线夹具使用。

在项目根目录，以后端现有venv运行以下命令会新建一次虚构库并提供最长20分钟的本机页面；需要本机网络执行权限时按固定脚本申请，不扩为一般网络权限：

```powershell
.\bishe\knowledge_graph_backend\.venv\Scripts\python.exe -B .\temp\run_natural_memory_r7_panel_20261030.py --serve
```

命令只打印新夹具目录，不打印凭据。在该目录读取 `server-info.json` 时仅输出 `port`，然后用浏览器打开 `http://127.0.0.1:<port>/`。实际页面提供虚构账号A/B/C的连接按钮及仅填草稿的样例。不要进入正式页面，不输入真实病情或真实账号。每次重启夹具都是新库，不能覆盖上一轮证据。

独立页面验收清单冻结于 `bishe/data/natural_memory_v1/r7_ui_acceptance.json`，结果均为null。必须记录实际点击、HTTP事件和截图；已完成的控制器检查不可代替这些观察。至少完成：

- A初始全关；分别调整收集、使用及各处理许可，刷新核对实际状态；关收集不把已保存数据显示成删除。
- A发送“我可能有银屑病。”：待确认时已保存列表为空；确认后仍为可能、有完整原话，不能显示医学确诊。
- 刷新浏览器后重新连接A，原已保存条目可回读；新建会话问“结合我之前说的情况，这份资料要关注什么？”：显示个人自述和专业依据两栏。一般知识/家属问题不带本人疾病。
- 选择旧银屑病条目并发送“更正一下，之前那条应是湿疹。”：先争议停用，确认后新回答依据为湿疹，不能继续引用旧银屑病。

- 暂停/恢复、撤销、遗忘及重置当前上下文；遗忘后刷新/换会话不能从旧来源重建；新的明确发言使用新消息ID，可以重新形成候选。
- 连接C，显式开启偏好收集、提取、自动偏好意愿，发送“以后回答简短一些。”：自动来源未逐条确认、无待确认卡；撤销后不再可用。C演示不用于真实语义门槛。
- “处理失败样例。”显示失败而非“已记住”；退出A后连接B，开关及内容均不继承。
- 桌面及390宽布局：表单、确认与遗忘说明、长原话、分栏依据、续做状态均可操作且无横向溢出。完成后恢复正常视口。

完成或受限后向夹具目录写入 `stop-requested`（不删除目录/文件），等待退出并保存实际退出状态。不要让20分钟自动停机替代人工收尾核对。实际UI观察全部完成前保持R7待验状态，之后再决定是否进入R8；真实模型测试、正式迁移和加载始终另行处理。
