# bishe_improve

医疗知识图谱 RAG Agent：基于已有问答项目改造，使用 DeepSeek Flash、Neo4j 图谱与全文检索，研究受约束工具调用、动态规划、任务工作记忆、会话状态、上下文选择和短期恢复。

## 文件分类与版本管理范围

| 路径 | 内容 | Git 管理方式 |
| --- | --- | --- |
| `bishe/knowledge_graph_backend/` | Django 服务、Agent 控制器、工具、状态及测试 | 纳入源码、依赖清单和配置模板；排除 `.env`、本地账号数据库和虚拟环境 |
| `bishe/knowledge-graph-frontend/` | Vue 聊天交互、会话状态和答案展示 | 纳入源码与锁文件；排除 `node_modules` 和构建输出 |
| `bishe/scripts/`、`bishe/examples/` | 数据准备、运行、只读核验、实验入口及示例 | 纳入；付费实验入口不构成新增调用授权 |
| `bishe/data/` | 原始知识数据、小型题集、样本、统计及历史结果 | 纳入原始 `medical.json` 与小型可复核资料；排除大体积可再生成导出、Neo4j库、备份和模型 |
| `Project/` | 阶段规划、合并过程记录、正式讲解、历史交接 | 纳入；历史交接保留日期加 `hdf` 命名 |
| `AGENTS.md`、`RAG-Agent改造方案.md` | 协作规则和总体方案 | 纳入 |
| `temp/` | 一次性脚本、日志、checkpoint与运行报告 | 仅本地保留 |
| `Old/` | 已退出使用的源码与历史归档 | 仅本地保留 |

排除只影响 Git 跟踪，不删除或移动本地文件。过程文档指向 `temp/` 或 `Old/` 的部分历史证据链接仅在原本机可用；仓库保留对应结果摘要，不声称所有历史运行产物都随仓库发布。

## 数据与运行边界

正式数据范围为 `medical_full_v1`：8,806 疾病、27,098 业务实体、301,314 关系。完整实体/关系导出和149,975个文本片段体积较大，不直接存入 Git。需要本地复现时，可先从原始 `medical.json` 使用 `build_full_medical_data.py`、`build_medical_text.py` 生成，按各脚本的帮助和数据说明选择输出路径；不要覆盖已有正式数据。数据库导入是独立写操作，需要明确目标及对应检查记录，不属于克隆仓库后的自动步骤。

环境配置以 `.env.example` 为模板，真实密钥、Neo4j认证信息、账号与聊天历史不上传。已有医学资料保持 `not_verified`；来源校验、模拟回归和有限真实验收不等价于医学审核或通用问答准确率。本地模型和向量路线已停用，不自动恢复、下载或追加付费测试。
